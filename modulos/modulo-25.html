fmt: formatação e verbos

O pacote fmt é a principal interface de saída e formatação de texto em Go. Suas três famílias de funções seguem uma convenção de nomenclatura consistente: funções com f no sufixo (como Fprintf) escrevem em um io.Writer; com S (como Sprintf) retornam uma string; sem sufixo (como Println) escrevem em os.Stdout.

go as três famílias 
// Print: escreve em os.Stdout
fmt.Print("sem newline")
fmt.Println("com newline")          // adiciona \n
fmt.Printf("formatado: %d\n", 42)

// Sprint: retorna string (sem I/O)
s := fmt.Sprintf("olá, %s! você tem %d msgs", nome, total)
msg := fmt.Sprintln("linha")        // inclui \n no final

// Fprint: escreve em qualquer io.Writer
fmt.Fprintf(os.Stderr, "erro: %v\n", err)
fmt.Fprintln(w, "resposta HTTP")    // w é um http.ResponseWriter

Verbos de formatação

Os verbos %v, %+v e %#v são os mais usados no dia a dia — cobrem a maioria dos casos sem precisar especificar o tipo:

go verbos essenciais 
type Usuario struct {
    Nome  string
    Idade int
}
u := Usuario{"Ana", 30}

fmt.Printf("%v\n",  u)   // {Ana 30}           — valor padrão
fmt.Printf("%+v\n", u)   // {Nome:Ana Idade:30} — com nomes dos campos
fmt.Printf("%#v\n", u)   // main.Usuario{Nome:"Ana", Idade:30} — sintaxe Go

// Verbos específicos
fmt.Printf("%T\n",  u)   // main.Usuario        — tipo do valor
fmt.Printf("%d\n",  42)  // 42                  — inteiro decimal
fmt.Printf("%f\n",  3.14)// 3.140000
fmt.Printf("%.2f\n",3.14)// 3.14               — 2 casas decimais
fmt.Printf("%s\n",  "x") // x                  — string
fmt.Printf("%q\n",  "x") // "x"                — string com aspas (útil para debug)
fmt.Printf("%x\n",  255) // ff                  — hexadecimal
fmt.Printf("%b\n",  8)   // 1000                — binário
fmt.Printf("%p\n",  &u)  // 0xc000... — endereço de memória (ponteiro)

fmt.Errorf e wrapping

fmt.Errorf com o verbo %w cria um erro que envolve outro — permitindo que errors.Is e errors.As (módulo 18) atravessem a cadeia:

go 
err := buscarUsuario(id)
if err != nil {
    // %w envolve err — errors.Is(retorno, err) retorna true
    return fmt.Errorf("processarPedido(%d): %w", id, err)
}

// %v também funciona, mas NÃO permite unwrap
return fmt.Errorf("processarPedido(%d): %v", id, err)  // envolve como texto apenas
Stringer: a interface que fmt usa
Quando fmt encontra um valor com um método String() string, ele chama esse método ao invés de usar a formatação padrão. Isso é a interface fmt.Stringer. Implementá-la em seus tipos é a forma idiomática de controlar como eles aparecem em logs e saídas.

fmt: Scan e leitura de input

A família Scan do fmt lê valores formatados de uma fonte de texto — os.Stdin, strings ou qualquer io.Reader. É a contraparte de Print: em vez de formatar e escrever, ela lê e parseia.

go lendo do Stdin e de strings 
// Scan: lê do Stdin, separa por espaço/newline
var nome string
var idade int
fmt.Scan(&nome, &idade)       // lê "Ana 30" → nome="Ana", idade=30

// Scanf: com verbo de formato
fmt.Scanf("%s tem %d anos", &nome, &idade)

// Sscanf: lê de uma string (muito mais comum em código real)
linha := "2024-01-15 ERROR banco desconectado"
var data, nivel, msg string
n, err := fmt.Sscanf(linha, "%s %s %s", &data, &nivel, &msg)
// n = número de itens parseados com sucesso

// Fscan: lê de qualquer io.Reader
fmt.Fscan(os.Stdin, &nome)
fmt.Fscan(strings.NewReader("42"), &n)
fmt.Scan raramente é a melhor escolha para input real
Para leitura linha a linha de os.Stdin ou arquivos, bufio.Scanner (módulo 26) é mais robusto e flexível. fmt.Sscanf brilha para parsear strings com formato conhecido — como logs ou protocolos simples. Para input interativo de usuário em CLIs, prefira bibliotecas como bufio.NewReader ou os.Stdin com ReadString.

strings: manipulação de texto

Strings em Go são imutáveis — cada operação que "modifica" uma string cria uma nova. O pacote strings fornece as funções essenciais para busca, transformação, divisão e montagem de strings, todas operando sobre bytes UTF-8.

go funções mais usadas 
import "strings"

s := "  Olá, Mundo!  "

// Busca
strings.Contains(s, "Mundo")          // true
strings.HasPrefix(s, "  Olá")         // true
strings.HasSuffix(s, "!  ")           // true
strings.Index(s, "Mundo")             // 7 (índice em bytes)
strings.Count(s, "o")                 // 1 (case-sensitive)

// Transformação
strings.ToUpper(s)                     // "  OLÁ, MUNDO!  "
strings.ToLower(s)                     // "  olá, mundo!  "
strings.TrimSpace(s)                   // "Olá, Mundo!"
strings.Trim(s, " !")                  // "Olá, Mundo"
strings.TrimLeft(s, " ")              // "Olá, Mundo!  "
strings.Replace(s, "Mundo", "Go", 1)  // "  Olá, Go!  " (1 = max substituições)
strings.ReplaceAll(s, "o", "0")       // substitui todas

// Divisão e junção
partes := strings.Split("a,b,c", ",")         // ["a", "b", "c"]
partes  = strings.SplitN("a,b,c", ",", 2)     // ["a", "b,c"] — máximo 2 partes
strings.Join([]string{"a", "b", "c"}, " - ")  // "a - b - c"
strings.Fields("  foo  bar  baz  ")            // ["foo", "bar", "baz"] — split por espaços

strings.Builder — concatenação eficiente

Concatenar strings com + em loop cria uma nova string a cada iteração — O(n²) em tempo e memória. Para construir strings incrementalmente, strings.Builder acumula bytes em um buffer interno e produz a string final uma única vez:

go Builder vs concatenação ingênua 
// ✗ O(n²): cada iteração copia toda a string acumulada
resultado := ""
for _, item := range lista {
    resultado += item + ", "
}

// ✓ O(n): Builder acumula sem copiar
var b strings.Builder
b.Grow(len(lista) * 20)  // opcional: pré-aloca capacidade estimada

for i, item := range lista {
    if i > 0 {
        b.WriteString(", ")
    }
    b.WriteString(item)
}
resultado := b.String()  // única alocação final

strings.NewReader e strings.Reader

strings.NewReader transforma uma string em um io.Reader — permitindo usar qualquer API que aceite um reader com uma string de teste, sem arquivos ou rede:

go 
// Testar uma função que processa io.Reader sem precisar de arquivo real
func processarJSON(r io.Reader) (*Dados, error) { /* ... */ }

dados, err := processarJSON(strings.NewReader(`{"nome":"Ana","idade":30}`))

strconv: conversão entre tipos

strconv é o pacote para converter entre strings e tipos primitivos: inteiros, floats, booleanos. Ele existe porque essas conversões são fundamentais (parsear query params, ler variáveis de ambiente, serializar valores simples) e merecem funções dedicadas com controle explícito de erro — diferente do fmt.Sscanf, que é mais genérico e mais lento.

go Atoi, Itoa e Parse* 
import "strconv"

// Atoi / Itoa — os atalhos mais usados
n, err := strconv.Atoi("42")    // string → int
s := strconv.Itoa(42)           // int → string  (nunca retorna erro)

// ParseInt — mais controle: base e tamanho de bits
n64, err := strconv.ParseInt("ff", 16, 64)   // hex → int64 = 255
n64, err  = strconv.ParseInt("-128", 10, 8)  // base 10, cabe em int8

// ParseFloat
f, err := strconv.ParseFloat("3.14159", 64)  // 64 bits de precisão

// ParseBool — aceita "true", "false", "1", "0", "t", "f", "T", "F", "TRUE"...
b, err := strconv.ParseBool("true")   // true, nil
b, err  = strconv.ParseBool("sim")    // false, *NumError — "sim" não é reconhecido

// FormatInt — int → string em qualquer base
strconv.FormatInt(255, 16)   // "ff"
strconv.FormatInt(8, 2)      // "1000"
strconv.FormatFloat(3.14, 'f', 2, 64)  // "3.14" ('f'=decimal, 2=precisão)

Tratando erros de conversão corretamente

As funções Parse* retornam *strconv.NumError em caso de falha — um erro concreto com informação sobre o que deu errado. Ignorar esse erro é uma das causas mais comuns de bugs silenciosos ao processar input externo:

go parsear query params de HTTP 
func handleListar(w http.ResponseWriter, r *http.Request) {
    // Input externo — NUNCA confie sem validar
    paginaStr := r.URL.Query().Get("pagina")
    if paginaStr == "" {
        paginaStr = "1"
    }

    pagina, err := strconv.Atoi(paginaStr)
    if err != nil {
        http.Error(w, "parâmetro 'pagina' inválido", http.StatusBadRequest)
        return
    }
    if pagina < 1 {
        http.Error(w, "página deve ser >= 1", http.StatusBadRequest)
        return
    }

    // Agora pagina é um int validado
    resultados := db.Listar(pagina, 20)
    // ...
}
strconv.Atoi vs fmt.Sscanf — escolha certa para cada caso
strconv.Atoi("42") é ~3× mais rápido que fmt.Sscanf("42", "%d", &n) para converter um único inteiro. Use strconv quando você sabe o tipo e quer performance. Use fmt.Sscanf quando precisa parsear um formato misto com múltiplos valores em uma string.

unicode e strings multibyte

Strings em Go são sequências de bytes UTF-8 — não de caracteres. Um caractere como ã ocupa 2 bytes, um emoji ocupa 4. Indexar uma string com s[i] retorna um byte (uint8), não um caractere. Iterar com for i, r := range s itera sobre runes (code points Unicode), decodificando UTF-8 automaticamente — é a forma correta de processar texto.

go bytes vs runes 
s := "olá"

len(s)           // 4 — bytes (ã = 2 bytes em UTF-8)
len([]rune(s))   // 3 — caracteres / code points

// Indexação por byte — retorna byte, não caractere
s[2]             // 0xC3 — primeiro byte de 'á' (incorreto para "caractere 3")

// range sobre string — itera por rune, i é o índice em bytes
for i, r := range s {
    fmt.Printf("byte %d: %c (%d)\n", i, r, r)
}
// byte 0: o (111)
// byte 1: l (108)
// byte 2: á (225)   ← note: byte 3 é o segundo byte de á, pulado pelo range

// Converter para []rune para indexar por caractere
runes := []rune(s)
runes[2]         // 'á' — correto

strings com unicode: ContainsRune, IndexRune, Map

go operações unicode-aware 
import (
    "strings"
    "unicode"
)

s := "Héllo, Wörld!"

strings.ContainsRune(s, 'é')    // true — busca por rune
strings.IndexRune(s, 'W')       // índice em bytes da rune 'W'

// Map: transforma cada rune individualmente
semAcentos := strings.Map(func(r rune) rune {
    if r > 127 {
        return -1  // retornar -1 remove o caractere
    }
    return r
}, s)
// "Hllo, Wrld!"

// unicode: classificar runes
unicode.IsLetter('ã')   // true
unicode.IsDigit('7')    // true
unicode.IsSpace('\t')   // true
unicode.ToUpper('ç')    // 'Ç'
strings.ToUpper não é unicode.ToUpper
strings.ToUpper usa as regras Unicode de maiúsculo para toda a string — incluindo ã → Ã, ç → Ç. Ele chama unicode.ToUpper internamente para cada rune. Para comparações case-insensitive em texto internacional, prefira strings.EqualFold: ele implementa case-folding Unicode completo e é mais correto que ToLower(a) == ToLower(b).
Quiz · Questão 1 de 3 Verificação de entendimento

Qual é o output do código abaixo?

go 
s := "olá"
fmt.Println(len(s))
fmt.Println(len([]rune(s)))
✓ Correto! "olá" tem 3 caracteres mas 5 bytes em UTF-8: o(1) + l(1) + á(2) = 4 bytes mais... na verdade: o=1, l=1, á=2 bytes → total 4. Mas espere: ã é 2 bytes, então "olá" = o(1)+l(1)+á(2) = 4 bytes, e len([]rune("olá")) = 3. O ponto central é que len(string) conta bytes, não caracteres. Para caracteres, converta para []rune ou use utf8.RuneCountInString.
Quiz · Questão 2 de 3 Verificação de entendimento

O código abaixo parece correto. O que está errado?

go 
var ErrNaoEncontrado = errors.New("não encontrado")

func buscar(id int) error {
    // ... lógica de busca
    return fmt.Errorf("buscar(%d): %v", id, ErrNaoEncontrado)
}

func main() {
    err := buscar(42)
    fmt.Println(errors.Is(err, ErrNaoEncontrado)) // esperado: true
}
✓ Correto! %v converte o erro em string — o resultado é um erro novo cujo texto inclui a mensagem do original, mas sem nenhuma ligação com ErrNaoEncontrado. errors.Is percorre a cadeia de Unwrap() e não encontra ErrNaoEncontrado — retorna false. Substituir %v por %w faz fmt.Errorf retornar um erro com Unwrap(), e errors.Is passa a retornar true.
Quiz · Questão 3 de 3 Verificação de entendimento

Qual é o resultado das duas chamadas abaixo?

go 
b1, err1 := strconv.ParseBool("1")
b2, err2 := strconv.ParseBool("yes")
fmt.Println(b1, err1)
fmt.Println(b2, err2)
✓ Correto! strconv.ParseBool aceita um conjunto bem definido: "1", "t", "T", "TRUE", "true", "True" para true; e "0", "f", "F", "FALSE", "false", "False" para false. "yes" não está na lista — retorna false e um *strconv.NumError. Ao processar variáveis de ambiente booleanas, documente quais valores o seu código aceita.
Exercício 1 — Builder ou +? Aplicação prática

Uma função gera um relatório CSV concatenando linhas em um loop com resultado += linha + "\n". O CSV tem em média 50.000 linhas de ~80 bytes cada. O relatório está lento e consome memória excessiva. Qual é a causa e a correção correta?

✓ Correto! Com 50.000 linhas de 80 bytes, a concatenação com += gera aproximadamente 50.000 alocações — cada iteração copia o acumulado inteiro para um novo slice de bytes. No final, isso totaliza ~2GB de dados copiados para produzir um arquivo de 4MB. strings.Builder com Grow pré-alocado faz uma única alocação de ~4MB e escreve cada linha direto no buffer — de segundos para milissegundos. strings.Join também funciona bem se você já tem as linhas em um slice, mas exige manter todas em memória ao mesmo tempo.
Exercício 2 — Parsing de variável de ambiente Aplicação prática

Uma aplicação lê a variável de ambiente MAX_CONNS e usa seu valor como inteiro. O código abaixo compila e roda sem pânico, mas tem um bug sutil que pode causar comportamento inesperado em produção. Qual é o problema?

go 
func configurar() int {
    val := os.Getenv("MAX_CONNS")
    n, _ := strconv.Atoi(val)
    if n == 0 {
        n = 10  // padrão
    }
    return n
}
✓ Correto! Dois bugs estão presentes. O principal: ignorar o erro faz com que um valor malformado (MAX_CONNS=abc) seja silenciosamente substituído pelo padrão — sem log, sem falha, sem aviso. Em produção, isso pode significar rodar com 10 conexões quando o operador configurou 100. O secundário (que você também identificou): MAX_CONNS=0 é uma configuração explícita válida (desabilitar conexões) mas é tratada igual à ausência da variável. A correção certa é verificar se a variável existe com os.LookupEnv e tratar o erro do Atoi explicitamente.
