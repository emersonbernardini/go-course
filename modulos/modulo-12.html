Declaração de funções

Funções são declaradas com a palavra-chave func, seguida do nome, lista de parâmetros entre parênteses, tipo de retorno e corpo entre chaves. Em Go, a chave de abertura fica na mesma linha da assinatura — como em todos os blocos.

go sintaxe 
func nomeDaFuncao(parametros) tipoDeRetorno {
    // corpo
    return valor
}
go exemplos 
// Sem parâmetros, sem retorno
func saudar() {
    fmt.Println("Olá!")
}

// Com parâmetros e retorno
func somar(a int, b int) int {
    return a + b
}

// Parâmetros do mesmo tipo — tipo pode ser declarado uma vez
func subtrair(a, b int) int {
    return a - b
}

// Sem retorno (void em outras linguagens)
func logar(msg string) {
    fmt.Println("[LOG]", msg)
}

Visibilidade: maiúscula exporta, minúscula não

A mesma regra de capitalização que vimos para variáveis e constantes se aplica a funções. Calcular é visível fora do pacote; calcular é privada ao pacote.

Ordem de declaração não importa

Como vimos no Módulo 03, o compilador faz duas passagens. Funções podem ser chamadas antes de serem declaradas no arquivo — sem necessidade de protótipos como em C.

go 
func main() {
    fmt.Println(dobrar(5))  // chama dobrar antes de declará-la — OK
}

func dobrar(n int) int {
    return n * 2
}

Parâmetros e retorno

Em Go, todos os argumentos são passados por valor — a função recebe uma cópia do dado. Para tipos de valor (int, string, bool, array, struct), modificações dentro da função não afetam o original. Para tipos de referência (slice, map, channel, ponteiro), a cópia do header ainda aponta para os mesmos dados subjacentes — modificações nos elementos afetam o original.

go passagem por valor 
// int é tipo de valor — cópia, original não muda
func incrementar(n int) {
    n++  // modifica apenas a cópia local
}

x := 10
incrementar(x)
fmt.Println(x)  // 10 — não mudou

// slice é referência — elementos compartilhados
func zerar(s []int) {
    for i := range s {
        s[i] = 0  // modifica o backing array original
    }
}

nums := []int{1, 2, 3}
zerar(nums)
fmt.Println(nums)  // [0 0 0] — mudou!

Parâmetros do mesmo tipo

Quando múltiplos parâmetros consecutivos têm o mesmo tipo, o tipo pode ser declarado apenas uma vez no final do grupo:

go 
// Verboso — tipo repetido
func retangulo(largura int, altura int, nome string) {}

// Idiomático — tipo compartilhado entre consecutivos
func retangulo(largura, altura int, nome string) {}

Quando usar ponteiro como parâmetro

Passe um ponteiro quando precisar modificar o valor original de um tipo de valor, ou quando o dado for grande e você quiser evitar o custo de cópia:

go 
// Modificar int original via ponteiro
func incrementarPtr(n *int) {
    *n++
}

x := 10
incrementarPtr(&x)
fmt.Println(x)  // 11

// Evitar cópia de struct grande
type Relatorio struct {
    Dados [10000]float64
    // ...
}

func processar(r *Relatorio) {  // ponteiro — sem copiar 80KB
    r.Dados[0] = 1.0
}

Múltiplos retornos

Go permite que funções retornem múltiplos valores. Esta é uma funcionalidade central da linguagem — a principal forma de retornar um resultado junto com um erro. Os tipos de retorno múltiplo ficam entre parênteses:

go múltiplos retornos 
// Retorna resultado e erro — padrão Go
func dividir(a, b float64) (float64, error) {
    if b == 0 {
        return 0, fmt.Errorf("divisão por zero")
    }
    return a / b, nil
}

// Usando a função
resultado, err := dividir(10, 3)
if err != nil {
    log.Fatal(err)
}
fmt.Printf("%.4f\n", resultado)  // 3.3333

// Descartando valores com _
resultado2, _ := dividir(20, 4)  // ignora o erro (só faça se for seguro)

Padrão (resultado, error)

A convenção em Go é retornar o erro como último valor de retorno. Quando há erro, os outros valores de retorno geralmente são zero values — embora isso não seja tecnicamente obrigatório. O chamador sempre verifica o erro antes de usar o resultado.

go convenção error como último retorno 
// ✓ Convenção correta — error por último
func abrirArquivo(nome string) (*os.File, error) {}
func parsearJSON(dados []byte) (Config, error)   {}
func buscarUsuario(id int) (*Usuario, error)     {}

// ✗ Fora da convenção — error no meio
func calcular(a int) (error, int) {}  // evite

Retornos não relacionados a erro

Múltiplos retornos também são usados para casos sem erro — como retornar o quociente e o resto de uma divisão, ou mín e máx:

go 
func minMax(nums []int) (min, max int) {
    min, max = nums[0], nums[0]
    for _, n := range nums[1:] {
        if n < min { min = n }
        if n > max { max = n }
    }
    return min, max
}

menor, maior := minMax([]int{3, 1, 4, 1, 5, 9, 2, 6})
fmt.Println(menor, maior)  // 1 9

Retornos nomeados

Go permite dar nomes às variáveis de retorno na assinatura da função. Elas são declaradas automaticamente com zero value e um return sem argumentos (naked return) retorna seus valores atuais:

go retornos nomeados 
func dividirNomeado(a, b float64) (resultado float64, err error) {
    if b == 0 {
        err = fmt.Errorf("divisão por zero")
        return  // naked return — retorna resultado (0.0) e err
    }
    resultado = a / b
    return  // naked return — retorna resultado e err (nil)
}

Quando usar retornos nomeados

A comunidade Go tem opiniões divididas sobre retornos nomeados. Há dois casos onde há consenso de que são úteis:

  • Documentação: nomear os retornos deixa claro o significado de cada valor sem precisar ler o corpo da função. Funções com múltiplos retornos do mesmo tipo se beneficiam disso.
  • Uso com defer para modificar o retorno: retornos nomeados permitem que funções defer modifiquem o valor de retorno — padrão útil para tratamento de erros. Veremos isso no Módulo 13.
go uso documentacional 
// Sem nomes — o que são esses dois ints?
func limites(s []int) (int, int) {}

// Com nomes — imediatamente claro
func limites(s []int) (min, max int) {}
Naked returns em funções longas são problemáticos
Em funções curtas, naked returns são aceitáveis. Em funções com mais de ~10 linhas, eles dificultam a leitura — o leitor precisa lembrar quais variáveis nomeadas existem e seus estados atuais. Prefira return resultado, err explícito em funções mais longas.

Funções como valores — first-class functions

Em Go, funções são valores de primeira classe: podem ser atribuídas a variáveis, passadas como argumentos, retornadas por outras funções e armazenadas em estruturas de dados. Isso habilita padrões funcionais poderosos sem a necessidade de objetos ou classes.

Atribuindo funções a variáveis

go 
// Função nomeada
func quadrado(n int) int { return n * n }

// Atribuindo a uma variável — o tipo é func(int) int
f := quadrado
fmt.Println(f(5))   // 25

// Função anônima (literal de função)
dobrar := func(n int) int { return n * 2 }
fmt.Println(dobrar(5))  // 10

// Invocação imediata (IIFE)
resultado := func(a, b int) int { return a + b }(3, 4)
fmt.Println(resultado)  // 7

Funções como parâmetros

O tipo de uma função é declarado como func(tipos_param) tipos_retorno:

go 
// aplicar recebe uma função como parâmetro
func aplicar(nums []int, f func(int) int) []int {
    resultado := make([]int, len(nums))
    for i, n := range nums {
        resultado[i] = f(n)
    }
    return resultado
}

nums := []int{1, 2, 3, 4, 5}

quadrados := aplicar(nums, func(n int) int { return n * n })
fmt.Println(quadrados)  // [1 4 9 16 25]

dobrados := aplicar(nums, func(n int) int { return n * 2 })
fmt.Println(dobrados)   // [2 4 6 8 10]

Funções retornando funções

Funções podem retornar outras funções — isso é a base para closures, que estudaremos no próximo módulo:

go 
// multiplicadorPor retorna uma função que multiplica por n
func multiplicadorPor(n int) func(int) int {
    return func(x int) int {
        return x * n
    }
}

dobrar := multiplicadorPor(2)
triplicar := multiplicadorPor(3)

fmt.Println(dobrar(5))    // 10
fmt.Println(triplicar(5)) // 15

Tipos de função nomeados

Você pode criar um tipo nomeado para uma assinatura de função, tornando o código mais legível — especialmente útil em handlers, middlewares e callbacks:

go 
// Sem tipo nomeado — verbose e repetitivo
func executar(f func(string) error) error {}
var handlers []func(string) error

// Com tipo nomeado — mais claro
type Handler func(string) error

func executar(f Handler) error {}
var handlers []Handler

// Exemplo real: http.HandlerFunc na stdlib é exatamente isso
// type HandlerFunc func(ResponseWriter, *Request)
Quiz · Questão 1 de 3 Verificação de entendimento

O que é impresso pelo código abaixo?

go 
func modificar(n int, s []int) {
    n = 99
    s[0] = 99
}

num := 1
nums := []int{1, 2, 3}
modificar(num, nums)
fmt.Println(num, nums[0])
✓ Correto! int é um tipo de valor — a função recebe uma cópia de num, e modificá-la não afeta o original. []int é um tipo de referência — o header é copiado, mas o ponteiro ainda aponta para o mesmo backing array. Modificar s[0] modifica nums[0].
Quiz · Questão 2 de 3 Verificação de entendimento

Qual assinatura segue corretamente a convenção de múltiplos retornos em Go para uma função que busca um usuário por ID?

✓ Correto! A convenção Go é sempre colocar o error como último valor de retorno. Isso é seguido por toda a stdlib e pela esmagadora maioria dos pacotes Go. Ferramentas de análise estática como errcheck dependem dessa convenção para detectar erros ignorados.
Quiz · Questão 3 de 3 Verificação de entendimento

Qual é o tipo correto do parâmetro f na função abaixo?

go 
func filtrar(nums []int, f ???) []int {
    var resultado []int
    for _, n := range nums {
        if f(n) {
            resultado = append(resultado, n)
        }
    }
    return resultado
}
✓ Correto! O corpo da função chama f(n) onde n é um int, e usa o resultado em um if — portanto f deve receber um int e retornar um bool. O tipo completo é func(int) bool. Esse padrão — filtrar com predicado — é um dos usos clássicos de funções como valores.
Exercício 1 — Análise de assinatura Aplicação prática

Uma função precisa receber uma lista de strings, aplicar uma transformação em cada uma (definida pelo chamador), e retornar a lista transformada. Qual assinatura está correta?

✓ Correto! A função de transformação recebe uma string (o elemento atual) e retorna uma string (o valor transformado). O tipo completo do parâmetro é func(string) string. O retorno da função principal é []string — a lista com os elementos transformados.
Exercício 2 — Retornos nomeados Aplicação prática

Qual afirmação sobre retornos nomeados em Go está correta?

✓ Correto! Retornos nomeados declaram variáveis com zero value no início da função. O naked return retorna os valores atuais dessas variáveis — que podem ter sido modificadas ao longo do corpo. Eles não são apenas documentacionais: afetam o comportamento, e podem ser modificados por funções defer.
