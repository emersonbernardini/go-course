time.Time

time.Time é o tipo central do pacote time. Ele representa um instante no tempo com precisão de nanosegundo, incluindo informação de fuso horário (*time.Location). Ao contrário de timestamps Unix simples (um inteiro), time.Time carrega o contexto de onde aquele instante foi registrado — o que é fundamental para formatação e aritmética correta com horário de verão.

go criação de instâncias 
// Instante atual com fuso horário local
agora := time.Now()

// Instante específico: time.Date(ano, mês, dia, hora, min, seg, ns, loc)
lançamento := time.Date(2009, time.November, 10, 23, 0, 0, 0, time.UTC)

// A partir de timestamp Unix (segundos desde 1970-01-01 UTC)
t := time.Unix(1699900800, 0)         // segundos + nanosegundos
t2 := time.UnixMilli(1699900800000)   // milissegundos (Go 1.17+)
t3 := time.UnixMicro(1699900800000000) // microssegundos (Go 1.17+)

// Zero value de time.Time: January 1, year 1, 00:00:00 UTC
var zero time.Time
fmt.Println(zero.IsZero())  // true

// Extrair componentes
fmt.Println(agora.Year())        // 2024
fmt.Println(agora.Month())       // November (tipo time.Month)
fmt.Println(int(agora.Month()))  // 11
fmt.Println(agora.Day())         // dia do mês
fmt.Println(agora.Hour())        // hora (0-23)
fmt.Println(agora.Minute())      // minuto
fmt.Println(agora.Second())      // segundo
fmt.Println(agora.Nanosecond())  // nanosegundo
fmt.Println(agora.Weekday())     // Sunday, Monday, ..., Saturday
fmt.Println(agora.YearDay())     // dia do ano (1-366)

Convertendo para timestamp Unix

go 
t := time.Now()

// Para armazenar em banco ou serializar — sempre UTC
fmt.Println(t.Unix())      // segundos desde epoch (int64)
fmt.Println(t.UnixMilli()) // milissegundos (int64)
fmt.Println(t.UnixMicro()) // microssegundos (int64)
fmt.Println(t.UnixNano())  // nanosegundos (int64) — cuidado: estoura em 2262

// Normalizar para UTC antes de armazenar
armazenar := t.UTC()
fmt.Println(armazenar.Location())  // UTC
time.Time não é comparável com ==
Dois valores time.Time que representam o mesmo instante mas em fusos horários diferentes não são iguais com == — o operador compara a representação interna, incluindo o fuso. Use sempre t1.Equal(t2) para comparar instantes independentemente do fuso horário. == só é seguro se ambos vierem de time.UTC.

time.Duration

time.Duration é um int64 que representa uma duração em nanosegundos. O pacote time expõe constantes nomeadas para as unidades comuns, o que torna o código legível sem ambiguidade — sem precisar adivinhar se 30 significa segundos, milissegundos ou minutos.

go constantes e composição 
// Constantes da stdlib
time.Nanosecond   // 1
time.Microsecond  // 1000
time.Millisecond  // 1000000
time.Second       // 1000000000
time.Minute       // 60000000000
time.Hour         // 3600000000000

// Compor durações — idioma Go: multiplicar a constante
timeout := 30 * time.Second         // 30s
intervalo := 500 * time.Millisecond // 500ms
janela := 2*time.Hour + 30*time.Minute + 15*time.Second  // 2h30m15s

// Usar em funções da stdlib
time.Sleep(500 * time.Millisecond)
ctx, cancel := context.WithTimeout(ctx, 10*time.Second)
defer cancel()

Inspecionando e convertendo durações

go 
d := 2*time.Hour + 35*time.Minute + 10*time.Second

// Métodos de conversão — retornam float64
fmt.Println(d.Hours())   // 2.5861...
fmt.Println(d.Minutes()) // 155.166...
fmt.Println(d.Seconds()) // 9310.0

// Representação legível por humanos
fmt.Println(d.String())  // "2h35m10s"

// Truncar e arredondar
fmt.Println(d.Truncate(time.Hour))   // 2h0m0s
fmt.Println(d.Round(time.Minute))    // 2h35m0s

// Parsear a partir de string
parsed, err := time.ParseDuration("1h30m45s")
if err != nil {
    log.Fatal(err)
}
fmt.Println(parsed.Hours())  // 1.5125

// Parsear formatos suportados: ns, us/µs, ms, s, m, h
// Combinações: "300ms", "1.5h", "2h45m"
Nunca use um número literal como Duration diretamente
time.Sleep(30) dorme por 30 nanosegundos, não 30 segundos — o que provavelmente não é o que você quer. Como Duration é int64, o compilador aceita o literal sem reclamar. Sempre use a multiplicação com a constante: time.Sleep(30 * time.Second).

Formatação e parsing

Go tem uma abordagem única para formatação de datas: em vez de tokens genéricos como %Y, %m ou YYYY-MM-DD, Go usa um instante de referência fixo como template. Esse instante é Mon Jan 2 15:04:05 MST 2006 — ou em números: 01/02 03:04:05PM '06 -0700.

O truque para memorizar: 1 2 3 4 5 6 7 corresponde a mês, dia, hora, minuto, segundo, ano, fuso. O formato que você quer para a saída é escrito usando esses valores de referência.

go Format — do Time para string 
t := time.Date(2024, time.March, 15, 14, 30, 45, 0, time.UTC)

// Referência: Mon Jan 2 15:04:05 MST 2006
// Mês=1, Dia=2, Hora=15, Min=04, Seg=05, Ano=2006, Fuso=MST/-0700

// Formatos comuns
fmt.Println(t.Format("2006-01-02"))                    // 2024-03-15
fmt.Println(t.Format("02/01/2006"))                    // 15/03/2024  (DD/MM/AAAA)
fmt.Println(t.Format("2006-01-02 15:04:05"))           // 2024-03-15 14:30:45
fmt.Println(t.Format("2006-01-02T15:04:05Z07:00"))     // 2024-03-15T14:30:45Z (RFC3339)
fmt.Println(t.Format("Monday, 02 January 2006"))       // Friday, 15 March 2024
fmt.Println(t.Format("Jan 2, 2006 at 3:04pm (MST)"))  // Mar 15, 2024 at 2:30pm (UTC)

// Constantes prontas da stdlib (evitam reescrever formatos comuns)
fmt.Println(t.Format(time.RFC3339))      // 2024-03-15T14:30:45Z
fmt.Println(t.Format(time.RFC3339Nano))  // 2024-03-15T14:30:45.000000000Z
fmt.Println(t.Format(time.DateTime))     // 2024-03-15 14:30:45  (Go 1.20+)
fmt.Println(t.Format(time.DateOnly))     // 2024-03-15            (Go 1.20+)
fmt.Println(t.Format(time.TimeOnly))     // 14:30:45              (Go 1.20+)

Parse — de string para time.Time

go time.Parse e time.ParseInLocation 
// time.Parse: layout + string de entrada
// O layout usa os mesmos valores de referência do Format
t, err := time.Parse("2006-01-02", "2024-03-15")
if err != nil {
    log.Fatal(err)
}
fmt.Println(t)  // 2024-03-15 00:00:00 +0000 UTC

// Parsear com horário e fuso
t, err = time.Parse(time.RFC3339, "2024-03-15T14:30:45-03:00")
if err != nil {
    log.Fatal(err)
}
fmt.Println(t.UTC())  // 2024-03-15 17:30:45 +0000 UTC

// time.Parse sem fuso no layout → resultado em UTC
// Use time.ParseInLocation quando a string não tem fuso mas você sabe qual é
loc, _ := time.LoadLocation("America/Sao_Paulo")
t, err = time.ParseInLocation("2006-01-02 15:04:05", "2024-03-15 14:30:45", loc)
if err != nil {
    log.Fatal(err)
}
fmt.Println(t)        // 2024-03-15 14:30:45 -0300 -03
fmt.Println(t.UTC())  // 2024-03-15 17:30:45 +0000 UTC
O layout e a string devem ter a mesma estrutura
time.Parse exige correspondência exata entre o layout e a string de entrada. time.Parse("2006-01-02", "15/03/2024") falha — o separador é diferente. Se a string vier de uma fonte externa (API, banco, formulário), sempre valide o err retornado e documente o formato esperado. Para formatos ambíguos como 01/02/03, prefira RFC3339 que é inequívoco.

Operações e comparações

O pacote time fornece um conjunto de métodos para aritmética e comparação de instantes. A regra fundamental é: Time ± Duration = Time e Time − Time = Duration. Você nunca soma dois Time — isso seria semanticamente absurdo.

go Add, Sub e Since/Until 
agora := time.Now()

// Add: Time + Duration → Time
daqui1h := agora.Add(1 * time.Hour)
ontem    := agora.Add(-24 * time.Hour)  // subtrai com negativo
proxMes  := agora.AddDate(0, 1, 0)      // AddDate(anos, meses, dias)
proxAno  := agora.AddDate(1, 0, 0)

// Sub: Time − Time → Duration
inicio := time.Date(2024, 1, 1, 0, 0, 0, 0, time.UTC)
elapsed := agora.Sub(inicio)
fmt.Println(elapsed.Hours())  // horas desde 2024-01-01

// Since e Until — atalhos comuns em produção
fmt.Println(time.Since(inicio))   // equivale a time.Now().Sub(inicio)
fmt.Println(time.Until(daqui1h))  // equivale a daqui1h.Sub(time.Now())

// Medir tempo de execução — padrão idiomático
start := time.Now()
operacaoCara()
fmt.Printf("levou %v\n", time.Since(start))

Comparando instantes

go 
t1 := time.Now()
t2 := t1.Add(5 * time.Second)

// Equal — compara o instante, ignora fuso horário
fmt.Println(t1.Equal(t2))  // false
// Nunca use == para comparar time.Time quando os fusos podem diferir

// Before e After
fmt.Println(t1.Before(t2))  // true  — t1 é anterior a t2
fmt.Println(t2.After(t1))   // true  — t2 é posterior a t1
fmt.Println(t1.After(t2))   // false

// Verificar se está dentro de um intervalo
func dentroDoIntervalo(t, inicio, fim time.Time) bool {
    return (t.Equal(inicio) || t.After(inicio)) &&
           (t.Equal(fim)    || t.Before(fim))
}

// Truncar — zerando componentes abaixo de uma precisão
t := time.Now()
fmt.Println(t.Truncate(time.Hour))   // arredonda para baixo à hora inteira
fmt.Println(t.Truncate(24*time.Hour)) // início do dia em UTC (cuidado com fuso)
AddDate lida com calendário — Add não
Add(30 * 24 * time.Hour) sempre soma exatamente 720 horas — ignora quantos dias tem o mês e horário de verão. AddDate(0, 1, 0) soma um mês calendario: de 31 de janeiro chega a 28 (ou 29) de fevereiro. Para lógica de negócio com calendário (vencimentos, prazos), sempre prefira AddDate.

Timer e Ticker

O pacote time fornece duas primitivas para executar código ao longo do tempo: time.Timer dispara uma vez após uma duração; time.Ticker dispara repetidamente em intervalos regulares. Ambos comunicam os disparos via channel, integrando naturalmente com select e goroutines.

time.Timer

go Timer — dispara uma vez 
// NewTimer retorna um Timer com channel C que recebe após a duração
timer := time.NewTimer(2 * time.Second)

// Bloqueia até o timer disparar
t := <-timer.C
fmt.Println("disparou às", t.Format(time.TimeOnly))

// Cancelar um timer antes de disparar
timer2 := time.NewTimer(10 * time.Second)
if !timer2.Stop() {
    // Stop retorna false se o timer já disparou — drenar o channel
    <-timer2.C
}

// Reset só é seguro após Stop (com dreno se necessário)
timer2.Reset(5 * time.Second)

// Forma atalho quando não precisa cancelar
// time.AfterFunc executa a função em nova goroutine após a duração
time.AfterFunc(1*time.Second, func() {
    fmt.Println("executou após 1 segundo")
})

// time.After — atalho para <-timer.C (cuidado: não permite cancelar o timer)
select {
case <-time.After(5 * time.Second):
    fmt.Println("timeout")
case resultado := <-operacao():
    fmt.Println("concluído:", resultado)
}

time.Ticker

go Ticker — dispara periodicamente 
// NewTicker dispara no channel C a cada intervalo
ticker := time.NewTicker(500 * time.Millisecond)
defer ticker.Stop()  // sempre parar o ticker para evitar goroutine leak

done := make(chan struct{})

go func() {
    for {
        select {
        case t := <-ticker.C:
            fmt.Println("tick às", t.Format("15:04:05.000"))
        case <-done:
            return
        }
    }
}()

time.Sleep(2 * time.Second)
close(done)  // sinaliza para a goroutine parar

// time.Tick — atalho sem possibilidade de parar (evite em produção)
// for t := range time.Tick(500 * time.Millisecond) {
//     fmt.Println(t)  // vazamento de goroutine se o loop parar
// }
Timer Ticker
Disparos Uma vez Repetidamente
Uso típico Timeout, delay, deadline Polling, métricas, heartbeat
Parar timer.Stop() ticker.Stop()
Atalho time.After(d) / time.AfterFunc Evitar time.Tick em produção
Sempre chame Stop() — nunca deixe Tickers vazando
Um Ticker não parado continua consumindo recursos indefinidamente. A goroutine interna do runtime que alimenta o channel C permanece ativa mesmo que ninguém mais esteja lendo. Em servers de longa duração, isso acumula goroutines e memória até o processo reiniciar. Use sempre defer ticker.Stop() imediatamente após criar o Ticker.

Fusos horários

Fusos horários são a fonte de muitos bugs silenciosos em sistemas que lidam com datas e horários. Go centraliza o gerenciamento de fusos no tipo *time.Location e expõe a base de dados IANA completa via time.LoadLocation. A regra de ouro para sistemas é: armazene sempre em UTC, converta para o fuso local apenas na exibição.

go Location e conversão de fuso 
// Localizações predefinidas
time.UTC   // *time.Location para UTC
time.Local // *time.Location do sistema operacional

// Carregar fuso pelo nome IANA (requer tzdata no sistema ou embed)
sp, err := time.LoadLocation("America/Sao_Paulo")
if err != nil {
    log.Fatal(err)
}

tokyo, err := time.LoadLocation("Asia/Tokyo")
if err != nil {
    log.Fatal(err)
}

// Converter um mesmo instante para diferentes fusos
agora := time.Now().UTC()

fmt.Println(agora.In(sp).Format("2006-01-02 15:04:05 MST"))    // horário de SP
fmt.Println(agora.In(tokyo).Format("2006-01-02 15:04:05 MST")) // horário de Tóquio
fmt.Println(agora.UTC().Format("2006-01-02 15:04:05 MST"))     // UTC

// In() não muda o instante — muda apenas a apresentação
fmt.Println(agora.Equal(agora.In(sp)))  // true — é o mesmo instante

time.FixedZone — fuso sem banco IANA

go 
// FixedZone cria um fuso com offset fixo em segundos (sem regras de horário de verão)
brst := time.FixedZone("BRT", -3*60*60)  // UTC-3

t := time.Date(2024, time.June, 15, 12, 0, 0, 0, brst)
fmt.Println(t)         // 2024-06-15 12:00:00 -0300 BRT
fmt.Println(t.UTC())   // 2024-06-15 15:00:00 +0000 UTC

// Cuidado: FixedZone não respeita horário de verão
// Para São Paulo (que tem horário de verão), use LoadLocation("America/Sao_Paulo")

tzdata embutido — binários portáveis

go embed do banco de fusos 
// Em containers minimalistas (alpine, scratch), o banco IANA pode não existir
// Solução: importar o pacote time/tzdata para embutir o banco no binário
import _ "time/tzdata"  // blank import — inclui tzdata no binário

// Após esse import, LoadLocation funciona em qualquer ambiente
loc, err := time.LoadLocation("America/Sao_Paulo")  // sempre funciona

// Alternativa: flag de build
// go build -tags timetzdata .

// O banco adiciona ~450KB ao binário — aceitável para a maioria dos serviços
Horário de verão e a armadilha do Truncate
t.Truncate(24 * time.Hour) trunca em múltiplos de 24h desde o epoch UTC — não retorna meia-noite no fuso local. Em dias de transição de horário de verão (quando o dia tem 23h ou 25h), isso pode retornar o horário errado. Para obter meia-noite no fuso local, extraia os componentes e reconstrua: time.Date(t.Year(), t.Month(), t.Day(), 0, 0, 0, 0, t.Location()).

Qual chamada produz corretamente a string "25/12/2024" a partir de t := time.Date(2024, 12, 25, 0, 0, 0, 0, time.UTC)?

✓ Correto! Go usa um instante de referência fixo como template: Mon Jan 2 15:04:05 MST 2006. Qual é o output do código abaixo?

go 
sp, _ := time.LoadLocation("America/Sao_Paulo")

t1 := time.Date(2024, 6, 15, 12, 0, 0, 0, time.UTC)

Exercício 1 — Bug de fuso horário em relatório Aplicação prática

Um sistema de vendas armazena timestamps em UTC no banco de dados. O relatório de vendas do dia deve agrupar pedidos por dia no fuso de São Paulo (UTC-3). O código abaixo está incorreto — qual é o problema e a correção?

go 
func diaDoRelatorio(t time.Time) string {
    // t vem do banco em UTC
    return t.Truncate(24 * time.Hour).Format("2006-01-02")
}
✓ Correto! Truncate(24 * time.Hour) arredonda para múltiplos de 24h desde o epoch UTC — ignora completamente o fuso de SP. Um pedido feito às 22h em SP (01h UTC do dia seguinte) seria agrupado no dia seguinte no relatório. A correção correta é converter o instante para o fuso de São Paulo com In(sp) e então reconstruir meia-noite naquele fuso com time.Date(). Armazenar em SP no banco é má prática: fusos mudam (o Brasil aboliu horário de verão em 2019), e datas armazenadas em fuso local ficam ambíguas em transições.
Exercício 2 — Ticker com vazamento de goroutine Aplicação prática

O código abaixo coleta métricas a cada segundo em um servidor HTTP de longa duração. Qual é o problema e como corrigi-lo?

go 
func iniciarColeta(ctx context.Context) {
    go func() {
        for range time.Tick(1 * time.Second) {
            coletarMetricas()
        }
    }()
}
✓ Correto! time.Tick cria um Ticker interno que nunca é exposto e, portanto, nunca pode ser parado. Mesmo que o contexto seja cancelado, a goroutine continua rodando indefinidamente — um goroutine leak clássico em servidores de longa duração. A correção é: ticker := time.NewTicker(1 * time.Second); defer ticker.Stop() e dentro do loop: select { case <-ticker.C: coletarMetricas(); case <-ctx.Done(): return }. Assim, quando o contexto for cancelado (shutdown do servidor, por exemplo), a goroutine encerra limpo e o Ticker é parado.
