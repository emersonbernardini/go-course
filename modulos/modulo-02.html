Como Go funciona: compilador e toolchain

Antes de instalar qualquer coisa, é importante entender o que acontece nos bastidores quando você executa um programa Go. Esse entendimento vai clarear muito do que veremos ao longo do curso.

O caminho do código até a execução

Quando você escreve um programa Go e o executa, o seguinte acontece:

  1. Você escreve código-fonte em arquivos .go
  2. O compilador Go lê esses arquivos, verifica tipos, resolve importações e gera código de máquina
  3. O linker junta tudo em um único binário executável
  4. O binário roda diretamente no sistema operacional, sem intermediários
bash fluxo simplificado 
codigo.go  →  compilador Go  →  código de máquina  →  binário executável
                              (verifica tipos,        (instrução nativas
                               resolve imports)        do sistema)

Diferente de Python (que interpreta linha a linha) ou Java (que compila para bytecode e roda na JVM), Go compila direto para o hardware. Não existe nenhuma camada intermediária em tempo de execução.

O que é o toolchain

Quando você instala Go, você não instala apenas um compilador. Você instala o toolchain — um conjunto completo de ferramentas oficiais que vivem sob o comando go:

Comando O que faz
go build Compila e gera o binário executável
go run Compila e executa em um único passo (sem gerar arquivo)
go test Executa os testes do projeto
go fmt Formata o código seguindo o estilo padrão Go
go vet Analisa o código em busca de erros comuns
go mod Gerencia o módulo e as dependências
go get Baixa e instala dependências externas
go doc Exibe a documentação de pacotes e símbolos
go run vs go build
go run é conveniente para experimentação — compila e executa imediatamente, mas não grava o binário em disco. go build gera o executável final que você distribui. Durante o curso, usaremos go run para testar exemplos rapidamente.

Instalação do Go

Go é distribuído oficialmente pelo Google em go.dev/dl. Sempre baixe diretamente da fonte oficial — evite versões de repositórios de sistema operacional que podem estar desatualizadas.

Linux

O método recomendado no Linux é extrair o tarball diretamente em /usr/local. Isso garante que o Go fique isolado do restante do sistema e seja fácil de atualizar ou remover.

bash Linux (x86-64) 
# 1. Baixe o tarball da versão mais recente em go.dev/dl
#    Substitua X.XX.X pela versão atual (ex: 1.23.0)
wget https://go.dev/dl/goX.XX.X.linux-amd64.tar.gz

# 2. Remove instalação anterior (se existir) e extrai a nova
sudo rm -rf /usr/local/go
sudo tar -C /usr/local -xzf goX.XX.X.linux-amd64.tar.gz

# 3. Adicione ao PATH no seu shell config (~/.bashrc, ~/.zshrc, ~/.config/fish/config.fish)
export PATH=$PATH:/usr/local/go/bin

# 4. Recarregue o shell e confirme
go version

macOS

No macOS você tem duas opções equivalentes: o instalador .pkg (que configura o PATH automaticamente) ou via Homebrew.

bash macOS 
# Opção A: instalador oficial
# Baixe o .pkg em go.dev/dl e execute — o PATH é configurado automaticamente

# Opção B: Homebrew
brew install go

# Confirme a instalação
go version

Windows

bash Windows 
# Opção A: instalador oficial
# Baixe o .msi em go.dev/dl e execute — o PATH é configurado automaticamente

# Opção B: winget
winget install GoLang.Go

# Confirme no PowerShell ou CMD
go version

Verificando a instalação

Em qualquer sistema, após instalar, abra um novo terminal e execute:

bash verificação 
go version
# Saída esperada (versão pode variar):
# go version go1.23.0 linux/amd64

Se o comando for reconhecido e exibir a versão, a instalação está correta. Se receber "command not found", o problema é no PATH — o diretório /usr/local/go/bin (Linux/macOS) ou o equivalente no Windows não está na variável de ambiente.

Abra um novo terminal após instalar
Alterações no PATH só têm efeito em terminais abertos após a mudança. Se você editou o arquivo de configuração do shell, feche e reabra o terminal — ou execute source ~/.bashrc (ou equivalente) para recarregar sem fechar.

GOPATH e GOROOT

Duas variáveis de ambiente causam muita confusão em quem está começando: GOROOT e GOPATH. Elas têm propósitos completamente diferentes e é importante entender cada uma.

GOROOT — onde o Go está instalado

GOROOT aponta para o diretório onde o toolchain Go foi instalado. É onde ficam o compilador, as ferramentas e a biblioteca padrão.

bash 
go env GOROOT
# Exemplo de saída:
# /usr/local/go

# Estrutura interna do GOROOT:
# /usr/local/go/
# ├── bin/        ← executáveis: go, gofmt
# ├── src/        ← código-fonte da stdlib
# ├── pkg/        ← pacotes pré-compilados da stdlib
# └── doc/        ← documentação
Você não precisa configurar GOROOT
O Go define GOROOT automaticamente com base em onde ele foi instalado. Você só precisaria alterá-lo manualmente em casos muito específicos de instalações customizadas — o que não é o caso para desenvolvimento normal.

GOPATH — seu espaço de trabalho

GOPATH aponta para o seu espaço de trabalho pessoal — o lugar onde Go armazena pacotes baixados, binários instalados via go install, e o cache de módulos.

Por padrão, o valor é $HOME/go no Linux/macOS e %USERPROFILE%\go no Windows. Você raramente precisa alterá-lo.

bash 
go env GOPATH
# Exemplo de saída:
# /home/usuario/go

# Estrutura interna do GOPATH:
# ~/go/
# ├── bin/        ← binários instalados com go install
# ├── pkg/        ← cache de módulos compilados
# └── src/        ← usado antes dos Go Modules (pré Go 1.11, hoje obsoleto)

A confusão histórica do GOPATH

Antes do Go 1.11 (2018), todo código Go obrigatoriamente precisava ficar dentro do GOPATH/src. Isso causava muita fricção e era amplamente criticado. Com a introdução dos Go Modules no Go 1.11, essa restrição foi eliminada.

Hoje você pode criar projetos Go em qualquer diretório do sistema. O GOPATH continua existindo, mas apenas para armazenar binários instalados e o cache de módulos — não mais o seu código-fonte.

Resumo prático
Não se preocupe com GOROOT nem GOPATH no dia a dia. Crie seus projetos onde quiser, inicialize com go mod init, e o Go cuida do resto. Estudaremos Go Modules em detalhes no Módulo 20.

Inspecionando o ambiente: go env

O comando go env é sua janela para o ambiente de configuração do Go. Ele exibe todas as variáveis que controlam o comportamento do toolchain. É o primeiro lugar a olhar quando algo não está funcionando como esperado.

bash go env — saída típica 
go env

# Saída (trecho das variáveis mais importantes):
GOROOT='/usr/local/go'
GOPATH='/home/usuario/go'
GOMODCACHE='/home/usuario/go/pkg/mod'
GOOS='linux'
GOARCH='amd64'
GOBIN=''
CGO_ENABLED='1'
GOVERSION='go1.23.0'

Conheça as variáveis mais importantes:

GOOS e GOARCH — compilação cruzada

GOOS define o sistema operacional alvo da compilação e GOARCH define a arquitetura de processador. Esses dois juntos são o que torna a compilação cruzada (cross-compilation) em Go trivial.

Compilação cruzada significa compilar para um sistema diferente do que você está usando. Em Go, isso funciona nativamente sem instalar nada extra:

bash compilação cruzada 
# Compilar para Windows a partir do Linux:
GOOS=windows GOARCH=amd64 go build -o programa.exe main.go

# Compilar para macOS a partir do Linux:
GOOS=darwin GOARCH=arm64 go build -o programa-mac main.go

# Compilar para Linux ARM (Raspberry Pi) a partir de qualquer sistema:
GOOS=linux GOARCH=arm64 go build -o programa-pi main.go
Por que isso é raro em outras linguagens
Em C/C++, compilar para outra plataforma exige instalar um cross-compiler específico — uma tarefa não trivial. Em Go, toda a stdlib foi escrita para suportar compilação cruzada nativamente. Isso é possível porque Go não depende de bibliotecas do sistema para funcionalidades básicas.

GOBIN — onde ficam os binários instalados

Quando você roda go install, o binário gerado vai para GOBIN. Se GOBIN estiver vazio, o Go usa GOPATH/bin. Para que esses binários sejam acessíveis no terminal, esse diretório precisa estar no seu PATH.

bash adicionando GOPATH/bin ao PATH 
# Adicione ao seu shell config:
export PATH=$PATH:$(go env GOPATH)/bin

# Ou de forma explícita:
export PATH=$PATH:$HOME/go/bin

Consultando uma variável específica

bash 
# Exibe apenas uma variável
go env GOPATH
go env GOOS
go env GOARCH

# Exibe múltiplas variáveis
go env GOOS GOARCH GOVERSION

Seu primeiro programa: Hello, World

Chegou a hora de escrever código. Vamos criar o programa mais simples possível em Go — e entender cada linha dele com precisão. Não existe nenhuma linha desnecessária aqui.

Criando o projeto

bash terminal 
# Crie um diretório para o projeto
mkdir hello-go
cd hello-go

# Inicialize o módulo Go (estudaremos isso a fundo no Módulo 20)
go mod init hello-go

# Crie o arquivo principal
touch main.go

O código

go main.go 
package main

import "fmt"

func main() {
    fmt.Println("Hello, World!")
}

Agora vamos dissecar cada linha, sem pular nada:

Linha 1: package main

Todo arquivo Go começa com uma declaração de pacote. package main é especial: indica que este arquivo faz parte do pacote executável. Em Go, apenas pacotes chamados main geram binários executáveis. Qualquer outro nome de pacote gera uma biblioteca — código que pode ser importado, mas não executado diretamente.

Linha 3: import "fmt"

import inclui outros pacotes no arquivo. fmt (abreviação de format) é um pacote da biblioteca padrão que oferece funções de formatação e saída de texto — entre elas, Println.

Uma característica importante do Go: importações não usadas são erro de compilação. Se você importar fmt mas não usar nenhuma de suas funções, o compilador recusa compilar. Isso evita código morto acumulando ao longo do tempo.

go erro — importação não utilizada 
package main

import "fmt" // ERRO: importado mas não utilizado

func main() {
    // fmt não é usado em lugar nenhum
}

// Erro de compilação:
// ./main.go:3:8: "fmt" imported and not used

Linha 5: func main()

func é a palavra-chave para declarar uma função. main é o nome especial que o compilador procura como ponto de entrada do programa — é a primeira função que executa quando você roda o binário. Todo programa executável em Go deve ter exatamente uma função main no pacote main.

Linha 6: fmt.Println("Hello, World!")

Chama a função Println do pacote fmt. O ponto (.) é o separador entre pacote e função. Println imprime o texto seguido de uma quebra de linha (print line). As aspas duplas delimitam uma string literal — uma sequência de texto.

Executando o programa

bash terminal 
# Modo rápido: compila e executa sem gerar arquivo
go run main.go
# Saída: Hello, World!

# Modo produção: gera o binário e executa separadamente
go build -o hello main.go
./hello
# Saída: Hello, World!
Variáveis declaradas e não usadas também são erro
Assim como importações, Go não compila se você declarar uma variável e não a usar. Essa regra, junto com as importações obrigatórias, elimina código morto por design. Veremos isso em detalhes no Módulo 04.

O que go mod init criou

Quando você rodou go mod init hello-go, o Go criou um arquivo go.mod no diretório. Ele identifica o módulo e declara a versão mínima do Go necessária:

go go.mod 
module hello-go

go 1.23

Por enquanto não se preocupe com os detalhes desse arquivo — o Módulo 20 cobre Go Modules completamente. O que importa agora: todo projeto Go moderno começa com go mod init.

Quiz · Questão 1 de 3 Verificação de entendimento

Qual é a diferença principal entre go run e go build?

✓ Correto! Ambos compilam o código com a mesma verificação completa de tipos. A diferença é que go run descarta o binário após executar — ideal para experimentação. go build grava o binário em disco para distribuição ou uso posterior.
Quiz · Questão 2 de 3 Verificação de entendimento

O que diferencia GOROOT de GOPATH?

✓ Correto! GOROOT = instalação do Go (você não mexe). GOPATH = seu espaço de trabalho pessoal, padrão em ~/go. Com Go Modules, você raramente precisará pensar em nenhuma das duas no dia a dia.
Quiz · Questão 3 de 3 Verificação de entendimento

Por que todo programa executável em Go deve começar com package main e ter uma função main()?

✓ Correto! O compilador Go usa package main como sinal para produzir um executável. Sem ele, o resultado é uma biblioteca — código que pode ser importado, mas não executado diretamente. A função main() dentro desse pacote é o ponto de entrada obrigatório.
Exercício 1 — Análise de código Aplicação prática

O código abaixo tem um erro que impede a compilação. Qual é o problema?

go main.go 
package main

import (
    "fmt"
    "os"
)

func main() {
    fmt.Println("Olá, Go!")
}
✓ Exato! Go trata importações não utilizadas como erro de compilação, não como aviso. A solução é remover "os" do import ou, se precisar importar sem usar (raro), usar o blank identifier: import _ "os". No dia a dia, simplesmente remova o que não usa.
Exercício 2 — Compilação cruzada Aplicação prática

Um desenvolvedor está no Linux e precisa distribuir seu programa para usuários Windows (64-bit). Qual comando gera o executável correto?

✓ Correto! A compilação cruzada em Go se faz definindo as variáveis de ambiente GOOS e GOARCH antes do comando go build. Não é necessária nenhuma ferramenta adicional — o suporte é nativo ao toolchain.
