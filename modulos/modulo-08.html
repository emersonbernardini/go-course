for clássico

Go tem apenas uma palavra-chave para laços: for. Não existe while, não existe do/while, não existe foreach. Toda forma de iteração é expressa com for — em diferentes configurações. Isso não é uma limitação; é a filosofia Go de ter uma única forma canônica para cada coisa.

A forma clássica tem três componentes separados por ponto e vírgula: inicialização, condição e pós-instrução.

go sintaxe 
for inicialização; condição; pós-instrução {
    // corpo
}
go exemplos 
// Contagem crescente
for i := 0; i < 5; i++ {
    fmt.Println(i)  // 0 1 2 3 4
}

// Contagem decrescente
for i := 10; i > 0; i-- {
    fmt.Println(i)  // 10 9 8 ... 1
}

// Passo diferente de 1
for i := 0; i <= 100; i += 10 {
    fmt.Println(i)  // 0 10 20 ... 100
}

Escopo da variável de controle

A variável declarada na inicialização do for existe apenas dentro do laço — incluindo o corpo e as outras duas expressões. Não vaza para o escopo externo.

go 
for i := 0; i < 3; i++ {
    fmt.Println(i)
}
// fmt.Println(i)  // ERRO: i não existe aqui

// Se precisar de i após o laço, declare fora
i := 0
for ; i < 3; i++ {
    fmt.Println(i)
}
fmt.Println("final:", i)  // 3

Componentes opcionais

Os três componentes do for clássico são todos opcionais. Você pode omitir qualquer um deles — mas os ponto e vírgula permanecem enquanto houver ao menos um dos outros dois:

go 
// Sem inicialização
i := 0
for ; i < 5; i++ {
    fmt.Println(i)
}

// Sem pós-instrução
for i := 0; i < 5; {
    fmt.Println(i)
    i++
}

// Sem inicialização e sem pós-instrução (vira um while — próximo tópico)
for ; condicao; {
    // ...
}

for como while

Quando você omite a inicialização e a pós-instrução, o for se comporta exatamente como um while de outras linguagens. Os ponto e vírgula também podem ser omitidos nesse caso — fica só a condição:

go for como while 
// Equivalente a while (condicao) { ... }
n := 1
for n < 100 {
    n *= 2
}
fmt.Println(n)  // 128 — primeiro valor >= 100

// Leitura de input até condição
scanner := bufio.NewScanner(os.Stdin)
for scanner.Scan() {
    linha := scanner.Text()
    if linha == "sair" {
        break
    }
    fmt.Println("lido:", linha)
}

Quando usar for-while vs for clássico

Use o for clássico (com os três componentes) quando a iteração é baseada em um contador com incremento previsível — percorrer índices de um array, repetir N vezes. Use o for com apenas condição quando a iteração depende de um estado que muda de forma não uniforme — aguardar uma conexão, processar até EOF, repetir enquanto uma flag for true.

for infinito

Um for sem nenhum componente cria um laço infinito. É a forma idiomática em Go para servidores, workers e qualquer processo que deve rodar indefinidamente até ser explicitamente interrompido:

go for infinito 
for {
    // executa para sempre — até break, return ou panic
}

Na prática, todo laço infinito tem alguma forma de saída — um break condicional, um return, ou um canal de cancelamento (veremos no Bloco 8 de concorrência). Eis padrões reais:

go padrões comuns 
// Padrão 1: servidor HTTP (simplificado)
for {
    conn, err := listener.Accept()
    if err != nil {
        log.Println("erro:", err)
        continue
    }
    go handleConn(conn)
}

// Padrão 2: loop de retry com limite
tentativas := 0
for {
    err := conectar()
    if err == nil {
        break  // sucesso — sai do loop
    }
    tentativas++
    if tentativas >= 3 {
        log.Fatal("falhou após 3 tentativas")
    }
    time.Sleep(time.Second)
}

// Padrão 3: menu interativo
for {
    opcao := lerOpcao()
    switch opcao {
    case "1":
        fazerAlgo()
    case "sair":
        return  // return também sai do for
    }
}
for {} é diferente de busy-wait
Um laço infinito vazio (for {}) consome 100% de um núcleo de CPU — é um busy-wait. Em código real, sempre deve haver uma operação de bloqueio dentro do laço: uma leitura de rede, uma leitura de canal, um time.Sleep ou similar. Caso contrário, você está desperdiçando CPU.

range — iteração idiomática

A forma for range é a maneira idiomática de iterar sobre coleções em Go. Funciona com arrays, slices, maps, strings e channels. Em cada iteração, range retorna dois valores: o índice (ou chave) e o valor do elemento atual.

range sobre slice e array

go 
nums := []int{10, 20, 30, 40}

// Índice e valor
for i, v := range nums {
    fmt.Printf("nums[%d] = %d\n", i, v)
}
// nums[0] = 10
// nums[1] = 20
// nums[2] = 30
// nums[3] = 40

// Apenas índice (omite o valor)
for i := range nums {
    fmt.Println(i)  // 0 1 2 3
}

// Apenas valor (descarta o índice com _)
for _, v := range nums {
    fmt.Println(v)  // 10 20 30 40
}

range sobre map

Ao iterar sobre um map, range retorna chave e valor. A ordem de iteração é não determinística — não há garantia de ordem entre execuções:

go 
capitais := map[string]string{
    "Brasil":   "Brasília",
    "França":   "Paris",
    "Japão":    "Tóquio",
}

for pais, capital := range capitais {
    fmt.Printf("%s → %s\n", pais, capital)
}
// Ordem pode variar a cada execução — isso é intencional

range sobre string — itera por rune, não byte

Ao usar range em uma string, Go itera sobre os runes (caracteres Unicode), não sobre os bytes. O índice é a posição em bytes do início do rune, e o valor é o rune em si. Isso é exatamente o comportamento correto para texto multilíngue:

go 
s := "Olá"

// range itera por rune
for i, r := range s {
    fmt.Printf("byte[%d] = %c (%d)\n", i, r, r)
}
// byte[0] = O (79)
// byte[1] = l (108)
// byte[2] = á (225)   ← índice 2, não 3, pois 'á' ocupa 2 bytes (posições 2 e 3)
// byte[4] = (97)     ← note: pulou o índice 3

// Compare com indexação direta (itera por byte):
for i := 0; i < len(s); i++ {
    fmt.Printf("s[%d] = %d\n", i, s[i])
}
// s[0]=79 s[1]=108 s[2]=195 s[3]=161 s[4]=0 ← bytes brutos de 'á' em UTF-8
Use range para strings — sempre
Se você precisa processar os caracteres de uma string, use range. Ele lida com UTF-8 corretamente. A indexação direta com s[i] opera em bytes — e partir um caractere multibyte ao meio produz resultados incorretos.

range sobre channel

range também funciona em channels — itera até o channel ser fechado. Estudaremos channels em profundidade no Módulo 22; por ora, a sintaxe:

go 
ch := make(chan int)

go func() {
    for i := 0; i < 5; i++ {
        ch <- i
    }
    close(ch)  // sem close, o range bloqueia para sempre
}()

for v := range ch {
    fmt.Println(v)  // 0 1 2 3 4
}

break e continue

break e continue controlam o fluxo dentro de um laço. Ambos afetam o laço mais interno em que estão — a menos que um label seja usado (próximo tópico).

break — encerra o laço

break termina a execução do laço imediatamente e passa o controle para a primeira instrução após o bloco do laço:

go 
// Busca linear — para ao encontrar
nums := []int{3, 7, 2, 9, 4}
alvo := 9
encontrado := -1

for i, v := range nums {
    if v == alvo {
        encontrado = i
        break  // para o laço imediatamente
    }
}

if encontrado >= 0 {
    fmt.Printf("encontrado no índice %d\n", encontrado)  // índice 3
}

continue — pula para a próxima iteração

continue interrompe a iteração atual e avança para a próxima, sem executar o restante do corpo do laço:

go 
// Imprime apenas números pares
for i := 0; i < 10; i++ {
    if i%2 != 0 {
        continue  // pula ímpares
    }
    fmt.Println(i)  // 0 2 4 6 8
}

// Filtra e processa — padrão comum
for _, linha := range linhas {
    if strings.HasPrefix(linha, "#") {
        continue  // ignora comentários
    }
    if linha == "" {
        continue  // ignora linhas vazias
    }
    processar(linha)
}

break dentro de switch dentro de for

Uma pegadinha importante: break dentro de um switch que está dentro de um for encerra o switch, não o for. Para encerrar o for de dentro de um switch, é necessário um label — próximo tópico.

go pegadinha clássica 
for i := 0; i < 5; i++ {
    switch i {
    case 3:
        break  // encerra o switch, NÃO o for
        // o for continua: i=4 ainda executa
    }
    fmt.Println(i)  // imprime 0 1 2 3 4 — o break não encerrou o for
}

Labels — controle de laços aninhados

Um label é um identificador que marca um laço (ou switch). Com ele, break e continue podem referenciar um laço específico — não apenas o mais interno. São escritos antes do laço, seguidos de dois pontos:

go break com label 
// Busca em matriz 2D — encerra ambos os laços ao encontrar
externo:
for i := 0; i < 3; i++ {
    for j := 0; j < 3; j++ {
        if i == 1 && j == 1 {
            fmt.Printf("encontrado em [%d][%d]\n", i, j)
            break externo  // encerra o laço marcado como "externo"
        }
    }
}
// Sem o label, break encerraria apenas o laço interno (j)
go continue com label 
// Pula para a próxima iteração do laço externo
externo:
for i := 0; i < 3; i++ {
    for j := 0; j < 3; j++ {
        if j == 1 {
            continue externo  // vai para o próximo i, ignorando j=2
        }
        fmt.Printf("[%d,%d] ", i, j)
    }
}
// Saída: [0,0] [1,0] [2,0]
// (j=1 e j=2 foram pulados em cada iteração de i)

Resolvendo a pegadinha do switch dentro do for

Labels também resolvem o problema do break dentro de um switch dentro de um for que vimos no tópico anterior:

go 
loop:
for i := 0; i < 5; i++ {
    switch i {
    case 3:
        break loop  // agora encerra o for, não o switch
    }
    fmt.Println(i)  // imprime 0 1 2 — para em 3
}

Quando usar (e quando não usar) labels

Labels são úteis em dois cenários genuínos: encerrar laços aninhados ao encontrar um resultado em uma busca 2D, e sair de um for de dentro de um switch. Fora disso, labels frequentemente indicam que a lógica poderia ser extraída para uma função separada — o que é quase sempre mais claro.

Labels não são goto
Go tem goto, mas ele é extremamente raro em código idiomático. Labels usados com break e continue são diferentes — eles só funcionam em laços e switches, seguindo um fluxo estruturado. Não é possível usar um label para pular para um bloco arbitrário do código.
Quiz · Questão 1 de 3 Verificação de entendimento

Qual é a diferença entre iterar sobre uma string com for i := 0; i < len(s); i++ e for i, v := range s?

✓ Correto! s[i] retorna um byte (uint8). range s retorna um rune (int32) — o caractere Unicode completo. Para strings com caracteres multibyte como "Olá", a indexação direta pode partir um caractere ao meio, produzindo valores incorretos. Use sempre range para processar caracteres.
Quiz · Questão 2 de 3 Verificação de entendimento

O que o código abaixo imprime?

go 
for i := 0; i < 4; i++ {
    switch i {
    case 2:
        break
    }
    fmt.Println(i)
}
✓ Correto! break encerra a estrutura mais interna onde está — neste caso, o switch. O for continua executando normalmente. Por isso o fmt.Println(i) é executado para todos os valores: 0, 1, 2 e 3. Para encerrar o for, seria necessário um label: break loop.
Quiz · Questão 3 de 3 Verificação de entendimento

Um desenvolvedor usa for k, v := range meuMap e precisa que os elementos sejam processados em ordem alfabética das chaves. O que ele deve fazer?

✓ Correto! A iteração sobre maps em Go é intencionalmente não-determinística — a ordem muda a cada execução. Para iterar em ordem: extraia as chaves com for k := range m, ordene com sort.Strings(chaves), e acesse o map com m[chave] dentro do laço ordenado. Não existe sortedmap na stdlib.
Exercício 1 — Análise de output Aplicação prática

Qual é o output do código abaixo?

go 
for i := 0; i < 5; i++ {
    if i == 2 {
        continue
    }
    if i == 4 {
        break
    }
    fmt.Println(i)
}
✓ Correto! Quando i==2, continue pula o Println e vai direto para i++. Quando i==4, break encerra o laço antes de chegar ao Println. Resultado: 0, 1, 3.
Exercício 2 — Labels Aplicação prática

O código abaixo deveria parar toda a iteração ao encontrar o número 5 na matriz. O que está errado e como corrigir?

go 
matriz := [][]int{{1, 2}, {3, 5}, {6, 7}}
for _, linha := range matriz {
    for _, v := range linha {
        if v == 5 {
            fmt.Println("encontrado!")
            break  // intenção: parar tudo
        }
    }
}
fmt.Println("continuou aqui")
✓ Correto! O break sem label encerra apenas o laço mais interno — o laço externo continua. A solução com label: marcar o laço externo com externo: e usar break externo dentro do laço interno. Alternativamente, extrair a lógica para uma função e usar return é geralmente mais claro em código real.
