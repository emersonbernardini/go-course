Inteiros

Go oferece uma família completa de tipos inteiros, com e sem sinal, em tamanhos variados. Cada tipo define precisamente o intervalo de valores que pode armazenar.

Tipo Tamanho Intervalo
int8 8 bits -128 a 127
int16 16 bits -32768 a 32767
int32 32 bits -2147483648 a 2147483647
int64 64 bits -9223372036854775808 a 9223372036854775807
uint8 8 bits 0 a 255
uint16 16 bits 0 a 65535
uint32 32 bits 0 a 4294967295
uint64 64 bits 0 a 18446744073709551615
int 32 ou 64 bits Depende da plataforma (64 bits em sistemas modernos)
uint 32 ou 64 bits Sem sinal, tamanho da plataforma

Qual usar no dia a dia

Na prática, use int para a maioria dos casos — contadores, índices, quantidades. Use os tipos específicos apenas quando o tamanho importa: protocolos de rede, arquivos binários, ou interfaces com bibliotecas C que exigem tipos exatos.

go 
contador := 0           // int — uso geral
var porta uint16 = 8080 // uint16 — porto de rede (0-65535)
var flag uint8 = 0xFF   // uint8 — byte, bitmask
id := int64(123456789)  // int64 — IDs grandes, timestamps Unix
Integer overflow em Go
Go não detecta overflow em tempo de execução — o valor simplesmente "enrola" (wrap around). Um int8 com valor 127, incrementado por 1, vira -128. Se isso é um problema no seu domínio, use tipos maiores ou valide os limites manualmente.

Ponto flutuante

Go tem dois tipos de ponto flutuante, seguindo o padrão IEEE 754: float32 (precisão simples, 32 bits) e float64 (precisão dupla, 64 bits). Literais flutuantes sem tipo explícito são sempre inferidos como float64.

go 
pi := 3.14159        // float64 (inferido)
var e float32 = 2.71 // float32 explícito

// Notação científica
avogadro := 6.022e23  // 6.022 × 10²³
electronVolt := 1.6e-19

fmt.Printf("%.2f\n", pi)    // 3.14 — 2 casas decimais
fmt.Printf("%e\n", avogadro) // 6.022000e+23

float32 vs float64

Use sempre float64 por padrão. Ele oferece precisão suficiente para quase todos os casos e é o tipo nativo dos processadores de 64 bits modernos — não há custo de performance. Use float32 apenas quando há restrição explícita de memória (ex: gráficos 3D, processamento de sinais com milhões de samples).

Ponto flutuante não é exato
Esta não é uma peculiaridade de Go — é uma limitação do padrão IEEE 754. 0.1 + 0.2 em Go resulta em 0.30000000000000004. Para valores monetários, nunca use float64. Use inteiros em centavos (int64) ou uma biblioteca de decimal de precisão arbitrária como shopspring/decimal.

bool

O tipo bool armazena um de dois valores: true ou false. Zero value é false.

go 
ativo := true
var logado bool  // false (zero value)

// Resultado de comparações é sempre bool
maior := 10 > 5        // true
igual := "a" == "b"   // false
diferente := 1 != 2   // true

// Operadores lógicos
ambos := ativo && logado   // AND — false
algum := ativo || logado   // OR  — true
negado := !ativo           // NOT — false
Go não converte outros tipos para bool
Em C, if (1) é verdadeiro e if (0) é falso. Em Go isso não existe — o if exige uma expressão booleana explícita. if x { } só compila se x for do tipo bool.

string — imutável e UTF-8

Em Go, string é uma sequência de bytes imutável. O encoding padrão é UTF-8 — o que significa que um caractere pode ocupar de 1 a 4 bytes. Isso tem implicações importantes que veremos no tópico sobre rune.

go strings básicas 
// Aspas duplas — string interpretada (aceita \n, \t, etc.)
s1 := "Olá, Mundo!\n"

// Backtick — string raw (literal, sem interpretação de escape)
s2 := `Olá, Mundo!\n`  // \n é literal aqui, não quebra de linha

// Concatenação com +
nome := "Go"
versao := "1.23"
completo := nome + " " + versao  // "Go 1.23"

// Comprimento em bytes (não em caracteres!)
fmt.Println(len("Go"))    // 2
fmt.Println(len("Olá"))   // 4 (ó ocupa 2 bytes em UTF-8)

Strings são imutáveis

Uma vez criada, uma string não pode ser modificada. Operações que "modificam" strings na verdade criam novas strings. Isso é importante para performance — concatenar strings em loop com + é ineficiente; use strings.Builder para isso:

go 
// Ineficiente — cria uma nova string a cada iteração
resultado := ""
for i := 0; i < 1000; i++ {
    resultado += "x"  // 1000 alocações de string
}

// Eficiente — strings.Builder reutiliza o buffer interno
import "strings"

var b strings.Builder
for i := 0; i < 1000; i++ {
    b.WriteString("x")
}
resultado := b.String()  // uma única alocação no final

Acessando bytes individuais

O operador de índice s[i] retorna o byte na posição i — não o caractere. Para iterar sobre caracteres (runes), use range, que estudaremos no Módulo 08:

go 
s := "Olá"

fmt.Println(s[0])         // 79 — valor do byte 'O' (tipo byte/uint8)
fmt.Println(string(s[0])) // "O"

// Substrings via slicing — opera em bytes
fmt.Println(s[0:2])  // "Ol" — bytes 0 e 1
// ATENÇÃO: s[0:3] pode partir um caractere multibyte ao meio

byte e rune

Go tem dois tipos especiais intimamente relacionados com strings: byte e rune. Ambos são aliases — nomes alternativos para tipos existentes.

byte — alias de uint8

byte é exatamente o mesmo que uint8 — um inteiro sem sinal de 8 bits (0 a 255). Representa um único byte de dados. É o tipo retornado ao indexar uma string (s[i]).

go 
var b byte = 65
fmt.Println(b)         // 65
fmt.Println(string(b)) // "A" — byte 65 é o caractere ASCII 'A'

// []byte — slice de bytes, muito comum para I/O
dados := []byte{72, 101, 108, 108, 111}
fmt.Println(string(dados)) // "Hello"

rune — alias de int32

rune é exatamente o mesmo que int32. Representa um ponto de código Unicode — um caractere, não um byte. Um rune pode representar qualquer caractere humano, de 'A' a '漢' a '🚀'.

Literais de caractere entre aspas simples são runes:

go 
var r rune = 'A'
fmt.Println(r)         // 65 — valor Unicode de 'A'
fmt.Println(string(r)) // "A"

r2 := '漢'
fmt.Println(r2)         // 28450 — ponto de código Unicode
fmt.Println(string(r2)) // "漢"

// Iterando sobre caracteres com range — retorna runes
s := "Olá"
for i, r := range s {
    fmt.Printf("posição %d: %c (%d bytes)\n", i, r, /* varia */)
}
len() conta bytes, não caracteres
len("Olá") retorna 4, não 3, porque á ocupa 2 bytes em UTF-8. Para contar caracteres (runes), use utf8.RuneCountInString("Olá") do pacote unicode/utf8, que retorna 3.

Conversão de tipos

Go é estritamente tipado: não existem conversões implícitas entre tipos numéricos. Mesmo que a conversão seja "óbvia" (de int para float64), você deve fazê-la explicitamente. Isso pode parecer verboso, mas elimina bugs silenciosos de truncamento e perda de precisão.

go conversão explícita 
var i int = 42
var f float64 = float64(i)  // conversão explícita
var u uint = uint(f)        // conversão explícita

// ERRO: tipos diferentes sem conversão
var x int = 10
var y float64 = 3.14
// soma := x + y  // ERRO: mismatched types int and float64
soma := float64(x) + y  // OK: converte x para float64

Truncamento ao converter

Conversões que reduzem o tamanho do tipo simplesmente descartam os bits mais significativos — sem erro, sem pânico. É sua responsabilidade garantir que o valor cabe no tipo destino:

go 
var grande int = 300
pequeno := int8(grande)   // 300 não cabe em int8 (-128 a 127)
fmt.Println(pequeno)      // 44 — resultado do truncamento (300 % 256 = 44)

// float para int trunca (não arredonda)
pi := 3.99
inteiro := int(pi)
fmt.Println(inteiro)  // 3 — não 4

Conversão string ↔ números

Converter entre string e tipos numéricos não é feito com cast direto — é feito com funções do pacote strconv:

go 
import "strconv"

// int → string
n := 42
s := strconv.Itoa(n)        // "42"

// string → int
n2, err := strconv.Atoi("123")
if err != nil {
    // "abc" não é um número válido
}

// string → float64
f, err := strconv.ParseFloat("3.14", 64)

// ARMADILHA: string(42) não converte para "42"
// Converte o int para o caractere com aquele ponto de código Unicode
fmt.Println(string(42))   // "*" — não "42"!

Tipagem estática na prática

Agora que conhecemos os tipos básicos, vale consolidar o que a tipagem estática de Go significa na prática — seus benefícios, suas exigências e os erros mais comuns que ela previne.

O que o compilador verifica

go erros detectados em compilação 
// 1. Atribuição de tipo incompatível
var x int = "olá"    // ERRO: cannot use "olá" (type string) as type int

// 2. Operação entre tipos diferentes
a := 10
b := 3.14
c := a + b           // ERRO: mismatched types int and float64

// 3. Comparação entre tipos diferentes
if 1 == "1" { }      // ERRO: mismatched types int and string

// 4. Retorno de tipo errado
func soma() int {
    return "resultado"  // ERRO: cannot use "resultado" as type int
}

Tipos definidos pelo usuário

Go permite criar novos tipos a partir de tipos existentes com type NomeNovo TipoBase. Mesmo que o tipo base seja idêntico, os dois tipos são distintos para o compilador:

go 
type Celsius float64
type Fahrenheit float64

var temp Celsius = 100
// var tempF Fahrenheit = temp  // ERRO: tipos distintos, mesmo base float64

// Conversão explícita necessária
tempF := Fahrenheit(temp*9/5 + 32)
fmt.Println(tempF)  // 212

Esse padrão é muito útil para dar semântica a valores primitivos — Celsius e Fahrenheit são claramente tipos diferentes, e o compilador impede que você os misture acidentalmente. Estudaremos tipos definidos com mais profundidade nos módulos sobre structs e interfaces.

Quiz · Questão 1 de 3 Verificação de entendimento

Qual é a diferença entre byte e rune em Go?

✓ Correto! byte = uint8 (1 byte, 0–255) e rune = int32 (4 bytes, ponto de código Unicode). A distinção importa ao trabalhar com strings multilíngues: len("Olá") retorna 4 (bytes), mas a string tem 3 caracteres (runes).
Quiz · Questão 2 de 3 Verificação de entendimento

O que fmt.Println(string(65)) imprime?

✓ Correto! string(65) interpreta 65 como um ponto de código Unicode e retorna o caractere correspondente: "A". Para converter o número 65 para a string "65", use strconv.Itoa(65) ou fmt.Sprintf("%d", 65).
Quiz · Questão 3 de 3 Verificação de entendimento

O código abaixo compila?

go 
var x int32 = 10
var y int64 = 20
fmt.Println(x + y)
✓ Correto! Go não faz promoção automática de tipos numéricos. int32 e int64 são tipos distintos mesmo sendo ambos inteiros. O compilador rejeita a operação com "mismatched types". A solução é converter explicitamente: int64(x) + y.
Exercício 1 — Escolha de tipo Aplicação prática

Um sistema precisa armazenar o preço de produtos em centavos (ex: R$ 19,90 = 1990 centavos). Preços podem chegar a R$ 999.999,99. Qual tipo é mais adequado para essa variável?

✓ Correto! Valores monetários nunca devem usar ponto flutuante devido à imprecisão do IEEE 754. Armazenar em centavos como int64 é a abordagem correta — exata, sem surpresas. R$ 999.999,99 = 99.999.999 centavos, que cabe em int32, mas int64 é mais seguro para crescimento futuro.
Exercício 2 — len() e strings UTF-8 Aplicação prática

Qual é o valor retornado por len("café")?

✓ Correto! "café" tem 4 caracteres mas 5 bytes: c(1) + a(1) + f(1) + é(2). O acento é é o ponto de código U+00E9, que em UTF-8 é codificado em 2 bytes (0xC3 0xA9). Para contar caracteres use utf8.RuneCountInString("café") → 4.
