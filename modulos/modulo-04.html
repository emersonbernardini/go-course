var — declaração explícita

Uma variável é um nome que referencia um valor armazenado na memória. Em Go, a forma mais explícita de declarar uma variável é com a palavra-chave var:

go sintaxe de var 
var nome tipo
var nome tipo = valor
var nome = valor  // tipo inferido pelo compilador
go exemplos 
package main

import "fmt"

func main() {
    var idade int           // declarada sem valor: recebe zero value (0)
    var nome string         // zero value de string é ""
    var ativo bool          // zero value de bool é false
    var preco float64 = 9.99 // declarada com valor explícito
    var cidade = "São Paulo" // tipo inferido como string

    fmt.Println(idade, nome, ativo, preco, cidade)
    // Saída: 0  false 9.99 São Paulo
}

Declaração em bloco

Assim como import, múltiplas variáveis podem ser declaradas em bloco. Isso é comum para variáveis no nível do pacote:

go 
var (
    host    string = "localhost"
    porta   int    = 8080
    debug   bool   = false
    versao  = "1.0.0"  // tipo inferido
)

Quando usar var

A declaração var é preferida em dois contextos: variáveis no nível do pacote (fora de funções), e variáveis dentro de funções quando você quer declarar sem atribuir valor imediatamente — deixando o zero value ser o estado inicial intencional.

Variável declarada e não usada é erro
Assim como importações não usadas, Go não compila se você declarar uma variável local com var ou := e nunca a usar. Isso não se aplica a variáveis no nível do pacote — apenas às locais de funções.

:= — declaração curta

O operador := é a forma mais comum de declarar variáveis dentro de funções em Go. Ele declara e atribui em uma única expressão, inferindo o tipo automaticamente.

go declaração curta 
package main

import "fmt"

func main() {
    nome := "Emerson"       // string
    idade := 30             // int
    altura := 1.75          // float64
    ativo := true           // bool

    fmt.Println(nome, idade, altura, ativo)
}

Declaração múltipla

:= pode declarar múltiplas variáveis de uma vez. Isso é especialmente útil ao capturar múltiplos retornos de funções — padrão muito comum em Go:

go 
// Múltiplas variáveis em uma linha
x, y := 10, 20

// Capturando múltiplos retornos (padrão Go)
resultado, err := fazerAlgo()
if err != nil {
    // trata erro
}

// Troca de valores sem variável temporária
a, b := 1, 2
a, b = b, a  // a=2, b=1 (note: = não :=, pois já foram declaradas)

Regra de redeclaração

Uma pegadinha importante: := em um bloco que já tem a variável declarada é um erro. Mas existe uma exceção: se pelo menos uma das variáveis do lado esquerdo for nova, Go reutiliza as existentes e declara apenas as novas.

go redeclaração 
x := 10
x := 20  // ERRO: x já foi declarada neste bloco

// OK: err já existe, mas resultado2 é nova
resultado, err := primeiraChamada()
resultado2, err := segundaChamada()  // err é reatribuída, resultado2 é nova

Restrição: apenas dentro de funções

:= não pode ser usado no nível do pacote — fora de funções. Nesse escopo, var é obrigatório. Tentar usar := fora de uma função é erro de compilação.

go 
package main

// ERRO: := não é permitido fora de funções
config := "producao"  // syntax error

// CORRETO: use var no nível do pacote
var config = "producao"

func main() {
    // Aqui := funciona normalmente
    local := "variável local"
    _ = local
}

Zero values — o valor padrão de tudo

Em Go, toda variável declarada sem valor inicial recebe automaticamente o zero value do seu tipo. Isso é garantido pela linguagem — não existe variável não-inicializada em Go. Esse detalhe elimina uma categoria inteira de bugs presentes em C, onde variáveis locais não-inicializadas contêm lixo de memória.

Tipo Zero value Observação
int, int64... 0 Todos os tipos numéricos inteiros
float32, float64 0.0 Ponto flutuante
bool false Booleano
string "" String vazia (não nil)
pointer nil Ponteiro nulo
slice, map, chan nil Nil não é o mesmo que vazio
struct {campos zerados} Cada campo recebe seu próprio zero value
go zero values em prática 
package main

import "fmt"

func main() {
    var i int
    var f float64
    var b bool
    var s string

    fmt.Printf("%d %f %t %q\n", i, f, b, s)
    // Saída: 0 0.000000 false ""
}

// Zero value de struct: cada campo recebe o seu
type Pessoa struct {
    Nome  string
    Idade int
    Ativo bool
}

var p Pessoa
// p.Nome  == ""
// p.Idade == 0
// p.Ativo == false
Zero value como design intencional
A stdlib de Go é projetada para que os zero values sejam úteis. Um sync.Mutex com zero value já está pronto para uso — não precisa de constructor. Um bytes.Buffer zerado já funciona como buffer vazio. Esse padrão é chamado de "zero value useful" e é considerado boa prática em Go.

const — valores imutáveis

Constantes são valores que nunca mudam durante a execução do programa. Em Go, são declaradas com const e avaliadas em tempo de compilação — não em tempo de execução. Isso as torna mais eficientes que variáveis e permite usos que variáveis não permitem, como tamanhos de arrays.

go declaração de constantes 
const Pi = 3.14159265358979
const Linguagem = "Go"
const MaxConexoes = 100
const Versao = 1

// Em bloco
const (
    StatusOK    = 200
    StatusErro  = 500
    NomeApp     = "MeuServico"
)

// Constantes são avaliadas em tempo de compilação:
const Dobro = MaxConexoes * 2  // 200 — válido
// var x = 10
// const Triple = x * 3  // ERRO: x não é constante

Constantes sem tipo explícito

Constantes em Go podem ser não-tipadas (untyped). Uma constante não-tipada tem precisão arbitrária e seu tipo é determinado apenas no momento em que é usada. Isso permite que a mesma constante seja usada em contextos de tipos diferentes sem conversão explícita:

go 
const N = 100  // não-tipada — funciona como int, float64, etc.

var i int     = N  // OK: N vira int
var f float64 = N  // OK: N vira float64
var b byte    = N  // OK: N vira byte

// Constante tipada — mais restrita
const M int = 100
var g float64 = M  // ERRO: M é int, não pode ir para float64 sem conversão
Quando usar const vs var
Use const para valores que são conhecidos em tempo de compilação e nunca mudam: limites, códigos de status, nomes fixos, valores matemáticos. Use var para tudo que pode mudar ou que depende de lógica em tempo de execução.

iota — enumerações em Go

Go não tem uma palavra-chave enum como Java ou C#. Em vez disso, usa iota — um contador especial disponível apenas em blocos const, que começa em 0 e incrementa automaticamente a cada constante do bloco.

go iota básico 
type DiaSemana int

const (
    Domingo  DiaSemana = iota  // 0
    Segunda                    // 1  (iota incrementa automaticamente)
    Terca                      // 2
    Quarta                     // 3
    Quinta                     // 4
    Sexta                      // 5
    Sabado                     // 6
)

iota em expressões

iota pode participar de expressões, tornando possível criar enumerações com valores não-lineares:

go iota em expressões 
// Potências de 2 — comum para bitmasks e permissões
type Permissao int

const (
    Leitura   Permissao = 1 << iota  // 1 << 0 = 1
    Escrita                           // 1 << 1 = 2
    Execucao                          // 1 << 2 = 4
)

// Combinando permissões com operador bitwise |
minhasPermissoes := Leitura | Escrita  // 1 | 2 = 3

// Verificando permissão
temLeitura := minhasPermissoes&Leitura != 0  // true

Pulando o primeiro valor com _

O identificador _ (blank identifier) descarta um valor. É comum usar _ = iota para pular o zero e começar as enumerações em 1:

go 
type Nivel int

const (
    _       Nivel = iota  // descarta o 0 — evita confusão com zero value
    Basico                // 1
    Intermediario         // 2
    Avancado              // 3
)

// Agora um Nivel com zero value não é um nível válido — é o zero value
var n Nivel  // n == 0 — claramente não-inicializado

Escopo de variáveis

O escopo de uma variável é a região do código onde ela existe e pode ser acessada. Em Go, o escopo é determinado pelos blocos delimitados por chaves { }.

Níveis de escopo

go escopos 
package main

import "fmt"

// Escopo de pacote — visível em todos os arquivos do pacote
var contadorGlobal = 0

func main() {
    // Escopo de função — visível apenas dentro de main
    mensagem := "olá"

    if true {
        // Escopo de bloco — visível apenas dentro deste if
        resultado := 42
        fmt.Println(mensagem, resultado)  // OK: mensagem é do escopo externo
    }

    // fmt.Println(resultado)  // ERRO: resultado não existe aqui
    fmt.Println(mensagem)  // OK
}

Shadowing — sobreposição de variáveis

Um escopo interno pode declarar uma variável com o mesmo nome de um escopo externo. A variável interna sobrepõe (shadow) a externa dentro do seu bloco. Isso é válido em Go, mas é uma fonte comum de bugs sutis — use com cuidado:

go shadowing 
x := 10
fmt.Println(x)  // 10

if true {
    x := 20  // nova variável x, sobrepõe a externa
    fmt.Println(x)  // 20
}

fmt.Println(x)  // 10 — a variável externa não foi modificada!

Pegadinha clássica com := e err

O shadowing mais frequente em código Go real acontece com a variável err dentro de blocos if:

go shadowing de err — bug sutil 
err := primeiraOperacao()

if err != nil {
    // Aqui err é a do escopo externo — correto
    fmt.Println("erro:", err)
}

if resultado, err := segundaOperacao(); err != nil {
    // ATENÇÃO: este err é uma nova variável, local a este if
    // O err do escopo externo não foi tocado
    fmt.Println("erro:", err)
}

// err aqui ainda é o resultado de primeiraOperacao()
// A segunda operação não alterou o err externo
go vet e staticcheck detectam shadowing
Ferramentas de análise estática como go vet e staticcheck avisam sobre shadowing problemático. Em editores com suporte a Go (VS Code + gopls, GoLand), o highlighting visual já diferencia variáveis sobrepostas.

Qual é o output do programa abaixo?

package main

import "fmt"

func main() {
    var n int
    var s string

Quiz · Questão 3 de 3 Verificação de entendimento

Quais são os valores de A, B e C?

go 
const (
    A = iota + 1
    B
    C
)
✓ Correto! Quando a primeira constante usa iota + 1, as seguintes repetem a mesma expressão com iota incrementado: A = 0+1 = 1, B = 1+1 = 2, C = 2+1 = 3. A expressão é herdada, mas o valor de iota avança a cada linha do bloco const.
Exercício 1 — Análise de código Aplicação prática

Quantos erros de compilação existem no código abaixo, e quais são?

go 
package main

func main() {
    var x int = 10
    y := 20
    z := x + y
}
✓ Correto! As três variáveis são declaradas mas o resultado nunca é utilizado (ex: impresso ou retornado). Go não compila código com variáveis locais não usadas. A solução seria adicionar fmt.Println(z) ou usar _ = z para descartar o valor intencionalmente.
Exercício 2 — Shadowing Aplicação prática

Qual é o output do programa abaixo?

go 
package main

import "fmt"

func main() {
    x := 1
    {
        x := 2
        fmt.Println(x)
    }
    fmt.Println(x)
}
✓ Correto! O x := 2 dentro do bloco cria uma variável nova que só existe dentro daquele bloco. O x externo permanece com valor 1. Isso é shadowing — válido em Go, mas fonte frequente de bugs quando não intencional.
