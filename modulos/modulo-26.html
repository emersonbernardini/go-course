As interfaces io.Reader e io.Writer

O pacote io define as duas interfaces mais importantes da stdlib do Go. Toda entrada e saída de dados — arquivos, conexões de rede, buffers em memória, respostas HTTP, compressão gzip — converge para essas duas interfaces minimalistas:

go definições no pacote io 
// Reader é qualquer coisa da qual se pode ler bytes
type Reader interface {
    Read(p []byte) (n int, err error)
}

// Writer é qualquer coisa na qual se pode escrever bytes
type Writer interface {
    Write(p []byte) (n int, err error)
}

A beleza dessas interfaces é o que elas não especificam. Não importa se a fonte é um arquivo em disco, uma conexão TCP, uma string em memória ou um gerador de bytes aleatórios — qualquer um satisfaz io.Reader. O código que consume um io.Reader funciona com todos eles sem modificação.

O contrato de Read

Entender o contrato exato de Read é essencial — ele tem comportamentos não-óbvios que causam bugs quando ignorados:

go contrato de Read — nuances importantes 
// Read preenche p com até len(p) bytes.
// Retorna o número de bytes lidos (0 <= n <= len(p)) e qualquer erro.
//
// Quando Read esgota os dados, retorna 0, io.EOF
// (ou n > 0, io.EOF — pode retornar dados E EOF na mesma chamada)
//
// Read PODE retornar menos bytes do que len(p) mesmo sem erro.
// Isso é legal e esperado — nunca assuma que um Read preenche o buffer completo.

func lerCompletoErrado(r io.Reader) ([]byte, error) {
    buf := make([]byte, 1024)
    n, err := r.Read(buf)  // ✗ pode retornar menos de 1024 bytes mesmo havendo mais
    return buf[:n], err
}

// Forma correta: io.ReadAll lê até EOF, fazendo múltiplos Reads internamente
func lerCompleto(r io.Reader) ([]byte, error) {
    return io.ReadAll(r)  // ✓ continua lendo até io.EOF
}

// Forma correta para tamanho conhecido: io.ReadFull
func lerExatamente(r io.Reader, n int) ([]byte, error) {
    buf := make([]byte, n)
    _, err := io.ReadFull(r, buf)  // ✓ erro se não conseguir ler exatamente n bytes
    return buf, err
}

Funções utilitárias do pacote io

go as funções mais usadas do io 
// io.Copy — copia de Reader para Writer até EOF, sem buffer intermediário na memória
// Ideal para arquivos grandes: nunca carrega tudo na memória de uma vez
n, err := io.Copy(destino, origem)         // retorna bytes copiados

// io.CopyN — copia exatamente n bytes
n, err = io.CopyN(destino, origem, 1024)

// io.ReadAll — lê tudo até EOF, retorna []byte
data, err := io.ReadAll(r)

// io.ReadFull — lê exatamente len(buf) bytes ou retorna erro
n, err = io.ReadFull(r, buf)

// io.Discard — Writer que descarta tudo (útil para drenar um Reader)
io.Copy(io.Discard, resp.Body)  // drena e fecha corretamente sem alocar memória

// io.MultiWriter — escreve em múltiplos Writers simultaneamente
mw := io.MultiWriter(arquivo, os.Stdout, hashWriter)
io.Copy(mw, origem)  // um Copy escreve no arquivo, na tela e calcula hash ao mesmo tempo

// io.TeeReader — lê de r e escreve tudo que leu em w (espelho de leitura)
tee := io.TeeReader(resp.Body, &buf)  // cada Read de tee também grava em buf
io.Copy(io.Discard, tee)              // força leitura completa; buf agora tem o conteúdo

Implementações na stdlib

A força das interfaces io.Reader e io.Writer está na quantidade de tipos que as implementam. Todo código que aceita essas interfaces automaticamente funciona com todos eles:

Tipo Pacote Implementa
*os.File os Reader, Writer
*bytes.Buffer bytes Reader, Writer
*strings.Reader strings Reader
*strings.Builder strings Writer
net.Conn net Reader, Writer
http.ResponseWriter net/http Writer
*gzip.Reader / *gzip.Writer compress/gzip Reader, Writer
io.ReadCloser, io.WriteCloser e io.ReadWriter
O pacote io define interfaces compostas combinando as básicas: io.ReadCloser = Reader + Closer, io.ReadWriter = Reader + Writer, io.ReadWriteSeeker = Reader + Writer + Seeker. http.Response.Body, por exemplo, é um io.ReadCloser — você lê com Read e fecha com Close ao terminar.

Composição de IO

A maior vantagem das interfaces io.Reader e io.Writer é que elas se compõem. Você pode envolver um Reader em outro para adicionar comportamento — sem modificar o Reader original, sem herança, sem wrappers frágeis. É o padrão Decorator aplicado a IO.

Encadeando transformações

go composição: arquivo → gzip → hash → destino 
// Cenário: baixar um arquivo, calcular seu hash SHA-256 e gravá-lo comprimido
// Tudo em uma única passagem, sem carregar o arquivo inteiro na memória

func downloadEComprimir(url, destPath string) ([]byte, error) {
    resp, err := http.Get(url)
    if err != nil {
        return nil, fmt.Errorf("download: %w", err)
    }
    defer resp.Body.Close()

    // Cria o arquivo de destino
    arquivo, err := os.Create(destPath)
    if err != nil {
        return nil, fmt.Errorf("criar arquivo: %w", err)
    }
    defer arquivo.Close()

    // Cadeia de Writers: gzip → arquivo
    gz, err := gzip.NewWriter(arquivo)
    if err != nil {
        return nil, fmt.Errorf("gzip: %w", err)
    }
    defer gz.Close()

    // hasher intercepta tudo que passa: calcula SHA-256 "de graça"
    hasher := sha256.New()

    // MultiWriter: escreve nos dois simultaneamente
    destino := io.MultiWriter(gz, hasher)

    // Uma única cópia: resp.Body → gzip → arquivo
    //                   resp.Body → hasher
    // Nada fica inteiro na RAM
    if _, err := io.Copy(destino, resp.Body); err != nil {
        return nil, fmt.Errorf("copiar: %w", err)
    }

    return hasher.Sum(nil), nil  // retorna hash SHA-256 do conteúdo
}

strings.NewReader — string como Reader

Quando uma função exige um io.Reader mas você só tem uma string, use strings.NewReader. Isso elimina a necessidade de criar arquivos temporários ou converter para []byte desnecessariamente:

go string como Reader — teste e utilidades 
// Decodificar JSON de uma string literal — útil em testes
input := `{"nome":"Ana","idade":30}`
var usuario struct {
    Nome  string `json:"nome"`
    Idade int    `json:"idade"`
}
json.NewDecoder(strings.NewReader(input)).Decode(&usuario)

// Testar uma função que aceita io.Reader sem criar arquivo temporário
func processarCSV(r io.Reader) ([][]string, error) { /* ... */ }

rows, _ := processarCSV(strings.NewReader("nome,email\nAna,ana@ex.com\n"))

// bytes.NewReader faz o mesmo para []byte
data := []byte{0x89, 0x50, 0x4E, 0x47}  // cabeçalho PNG
formato, _ := detectarFormato(bytes.NewReader(data))

bytes.Buffer — Reader e Writer em memória

go bytes.Buffer como buffer de memória 
var buf bytes.Buffer

// Escreve de múltiplas formas
buf.WriteString("linha 1\n")
fmt.Fprintf(&buf, "linha %d\n", 2)  // Fprintf aceita io.Writer
buf.Write([]byte("linha 3\n"))

// Lê como Reader
scanner := bufio.NewScanner(&buf)
for scanner.Scan() {
    fmt.Println(scanner.Text())
}

// Ou lê tudo de uma vez
fmt.Println(buf.String())  // converte para string sem cópia extra em Go 1.10+

// Caso de uso real: construir corpo de requisição HTTP
var body bytes.Buffer
json.NewEncoder(&body).Encode(payload)
http.Post(url, "application/json", &body)
bytes.Buffer vs strings.Builder
Para construir strings por concatenação, prefira strings.Builder — ele não implementa io.Reader (só Writer), mas é otimizado para crescimento incremental e não faz cópias desnecessárias. bytes.Buffer é melhor quando você precisa tanto escrever quanto ler do mesmo buffer, ou quando trabalha com dados binários ([]byte).

bufio: leitura eficiente

Cada chamada a Read ou Write diretamente em um arquivo ou conexão de rede pode resultar em uma chamada de sistema — caro. O pacote bufio adiciona uma camada de buffer entre seu código e o IO real: agrupa muitas operações pequenas em poucas operações grandes, reduzindo drasticamente o número de syscalls.

bufio.Scanner — linha por linha

O jeito mais idiomático de ler um arquivo linha por linha em Go:

go Scanner — leitura linha a linha 
arquivo, err := os.Open("dados.txt")
if err != nil {
    log.Fatal(err)
}
defer arquivo.Close()

scanner := bufio.NewScanner(arquivo)

// Scan() retorna true enquanto houver linhas; false em EOF ou erro
for scanner.Scan() {
    linha := scanner.Text()  // string sem o \n final
    fmt.Println(linha)
}

// Verificar erro APÓS o loop — Scan() não retorna erro, apenas false
if err := scanner.Err(); err != nil {
    log.Printf("erro ao ler: %v", err)
}
// Não verificar scanner.Err() é um bug comum — EOF e erro real dão o mesmo false

Scanner com SplitFunc personalizado

Por padrão, Scanner separa por linhas. É possível configurar outros separadores — palavras, bytes individuais, ou qualquer lógica customizada:

go split functions 
// ScanWords — separa por espaços/tabs/newlines
scanner := bufio.NewScanner(strings.NewReader("go é simples e poderoso"))
scanner.Split(bufio.ScanWords)
for scanner.Scan() {
    fmt.Println(scanner.Text())  // "go", "é", "simples", "e", "poderoso"
}

// ScanBytes — byte a byte
scanner.Split(bufio.ScanBytes)

// ScanRunes — runa a runa (correto para UTF-8)
scanner.Split(bufio.ScanRunes)

// SplitFunc customizado — separa por vírgula (CSV simples)
scanner.Split(func(data []byte, atEOF bool) (advance int, token []byte, err error) {
    for i, b := range data {
        if b == ',' {
            return i + 1, data[:i], nil  // consome até a vírgula
        }
    }
    if atEOF && len(data) > 0 {
        return len(data), data, nil  // último campo sem vírgula
    }
    return 0, nil, nil  // aguarda mais dados
})

bufio.Reader — controle granular

bufio.Scanner é conveniente mas limitado: não funciona bem com linhas maiores que o buffer padrão (64KB). Para controle maior, use bufio.Reader diretamente:

go bufio.Reader — controle fino 
reader := bufio.NewReader(arquivo)

// ReadString lê até o delimitador (inclusivo)
linha, err := reader.ReadString('\n')
// linha inclui o '\n' — diferente de scanner.Text() que remove

// ReadBytes — igual mas retorna []byte
bytes, err := reader.ReadBytes('\n')

// ReadLine — baixo nível, evite em código novo
// Não retorna o '\n', mas também não funciona bem com linhas muito longas

// Peek — lê sem consumir (útil para detecção de formato)
cabecalho, err := reader.Peek(4)  // olha os próximos 4 bytes sem avançar
if bytes.Equal(cabecalho, []byte{0x89, 0x50, 0x4E, 0x47}) {
    fmt.Println("arquivo PNG detectado")
}

bufio.Writer — escrita com buffer

go bufio.Writer — flush obrigatório 
arquivo, _ := os.Create("saida.txt")
defer arquivo.Close()

// bufio.Writer agrupa writes — menos syscalls, mais performance
w := bufio.NewWriter(arquivo)

for i := 0; i < 10000; i++ {
    fmt.Fprintf(w, "linha %d\n", i)  // escreve no buffer interno
}

// CRÍTICO: Flush envia o buffer restante para o arquivo
// Sem Flush, os últimos bytes podem ficar no buffer e nunca chegarem ao disco
if err := w.Flush(); err != nil {
    log.Printf("erro ao fazer flush: %v", err)
}

// Padrão idiomático com defer — mas atenção: defer não captura erro de Flush
defer w.Flush()  // ✓ simples, mas ignora o erro de flush
// Para capturar o erro de flush com defer, use uma função nomeada
Esquecer Flush é um bug silencioso
bufio.Writer mantém dados em memória até o buffer encher (padrão 4096 bytes) ou até Flush() ser chamado. Se o programa terminar, ou o arquivo for fechado, sem um Flush(), os dados no buffer são perdidos silenciosamente. Nenhum erro é retornado — o arquivo simplesmente ficará incompleto. Sempre verifique o erro de Flush(), especialmente antes de fechar o arquivo.

Arquivos e sistema de arquivos com os

O pacote os é a interface do Go com o sistema operacional. Abrir, criar, renomear, remover arquivos; ler variáveis de ambiente; manipular diretórios — tudo passa por os. As funções retornam error idiomático e *os.File implementa tanto io.Reader quanto io.Writer.

Abrir e criar arquivos

go os.Open, os.Create e os.OpenFile 
// os.Open — somente leitura; erro se não existir
f, err := os.Open("entrada.txt")
defer f.Close()

// os.Create — cria ou trunca para escrita; cria se não existir
f, err = os.Create("saida.txt")
defer f.Close()

// os.OpenFile — controle total com flags e permissões
f, err = os.OpenFile("log.txt",
    os.O_APPEND|os.O_CREATE|os.O_WRONLY,  // abre para append, cria se não existir
    0644,                                   // permissões Unix: rw-r--r--
)

// Flags mais comuns:
// os.O_RDONLY  — somente leitura (valor 0)
// os.O_WRONLY  — somente escrita
// os.O_RDWR    — leitura e escrita
// os.O_CREATE  — cria se não existir
// os.O_TRUNC   — trunca ao abrir (apaga conteúdo existente)
// os.O_APPEND  — escreve sempre no final

// Atalho para arquivo inteiro — os.ReadFile / os.WriteFile (Go 1.16+)
data, err := os.ReadFile("config.json")    // lê tudo de uma vez
err = os.WriteFile("saida.json", data, 0644)  // escreve tudo de uma vez

Informações e metadados

go os.Stat — metadados de arquivo 
info, err := os.Stat("arquivo.txt")
if err != nil {
    if errors.Is(err, os.ErrNotExist) {
        fmt.Println("arquivo não existe")
    } else {
        log.Fatal(err)
    }
}

fmt.Println(info.Name())       // "arquivo.txt"
fmt.Println(info.Size())       // tamanho em bytes
fmt.Println(info.ModTime())    // última modificação
fmt.Println(info.IsDir())      // é diretório?
fmt.Println(info.Mode())       // permissões: -rw-r--r--

// Verificar se arquivo existe — padrão idiomático
func existeArquivo(path string) bool {
    _, err := os.Stat(path)
    return !errors.Is(err, os.ErrNotExist)
    // NUNCA use: err == nil — outros erros (permissão) dariam false incorretamente
}

Manipulação de diretórios

go diretórios e navegação 
// Criar diretório
os.Mkdir("dados", 0755)           // um nível
os.MkdirAll("a/b/c/d", 0755)     // cria toda a hierarquia (como mkdir -p)

// Listar conteúdo — os.ReadDir (Go 1.16+, substitui ioutil.ReadDir)
entradas, err := os.ReadDir(".")
for _, e := range entradas {
    fmt.Printf("%s  dir=%v  size=%d\n",
        e.Name(), e.IsDir(), /* tamanho requer e.Info() */ 0)

// Percorrer recursivamente — filepath.WalkDir (mais eficiente que filepath.Walk)
filepath.WalkDir(".", func(path string, d fs.DirEntry, err error) error {
    if err != nil {
        return err  // erro ao acessar este path — continua ou para
    }
    if d.IsDir() && d.Name() == "node_modules" {
        return filepath.SkipDir  // pula diretório inteiro
    }
    fmt.Println(path)
    return nil
})

// Remover
os.Remove("arquivo.txt")       // remove arquivo ou diretório vazio
os.RemoveAll("diretorio/")     // remove recursivamente (como rm -rf)

// Renomear / mover
os.Rename("velho.txt", "novo.txt")
os.Rename("arquivo.txt", "subdir/arquivo.txt")  // mover entre diretórios

Arquivo temporário e variáveis de ambiente

go temporários e ambiente 
// Arquivo temporário — criado no diretório de temp do SO
tmp, err := os.CreateTemp("", "processo-*.json")
// "" = diretório padrão (os.TempDir()); "*.json" = sufixo
defer os.Remove(tmp.Name())  // limpa após uso

// Diretório temporário

    fmt.Println("porta configurada:", val)
} else {
    fmt.Println("PORT não definida, usando padrão 8080")
}

// Todos os pares key=value do ambiente
for _, pair := range os.Environ() {
    fmt.Println(pair)  // "DATABASE_URL=postgres://..."
}

// Diretórios especiais

fmt.Println(os.Getwd())       // diretório de trabalho atual

filepath vs path — use sempre filepath
Go tem dois pacotes para manipular caminhos: path usa sempre / como separador e é para URLs e caminhos lógicos. path/filepath usa o separador nativo do SO (/ no Unix, \ no Windows) e deve ser usado para caminhos de arquivo reais. filepath.Join, filepath.Dir, filepath.Base e filepath.Ext são as funções que você usará no dia a dia.
Quiz · Questão 1 de 3 Verificação de entendimento

O código abaixo tenta ler exatamente 100 bytes de uma conexão de rede. Qual é o problema?

go 
func ler100Bytes(conn net.Conn) ([]byte, error) {
    buf := make([]byte, 100)
    n, err := conn.Read(buf)
    if err != nil {
        return nil, err
    }
    return buf[:n], nil
}
✓ Correto! O contrato de Read permite retornar entre 1 e len(buf) bytes sem erro — uma leitura parcial é completamente válida. Em conexões de rede, dados chegam em pacotes e uma única chamada Read pode retornar apenas o que chegou até aquele momento. A correção para ler exatamente N bytes é io.ReadFull(conn, buf) — ele faz múltiplos Read internamente até preencher o buffer ou encontrar um erro.
Quiz · Questão 2 de 3 Verificação de entendimento

O arquivo saida.txt gerado pelo código abaixo está vazio (0 bytes) mesmo sem nenhum erro reportado. Por quê?

go 
func gravar() error {
    f, err := os.Create("saida.txt")
    if err != nil {
        return err
    }
    defer f.Close()

    w := bufio.NewWriter(f)
    fmt.Fprintln(w, "linha importante")
    fmt.Fprintln(w, "outra linha")

    return nil  // retorna sem chamar w.Flush()
}
✓ Correto! bufio.Writer acumula dados em um buffer interno (padrão 4096 bytes). Só envia ao Writer subjacente (o arquivo) quando o buffer enche ou Flush() é chamado. Como as duas linhas somam bem menos que 4096 bytes, elas ficam no buffer e nunca chegam ao arquivo. defer f.Close() fecha o arquivo, não o bufio.Writer — o buffer é descartado. A correção: adicionar w.Flush() antes de retornar, ou usar defer w.Flush() logo após criar o writer.
Quiz · Questão 3 de 3 Verificação de entendimento

Qual das implementações abaixo verifica corretamente se um arquivo existe?

go 
// Opção A
func existeA(path string) bool {
    _, err := os.Stat(path)
    return err == nil
}

// Opção B
func existeB(path string) bool {
    _, err := os.Stat(path)
    return !errors.Is(err, os.ErrNotExist)
}

// Opção C
func existeC(path string) bool {
    f, err := os.Open(path)
    if err != nil { return false }
    f.Close()
    return true
}

// Opção D
func existeD(path string) bool {
    return os.Stat(path) != nil
}
✓ Correto! A Opção A parece certa mas é subtilmente incorreta: se o arquivo existe mas você não tem permissão de leitura, os.Stat retorna um erro de permissão — e a Opção A reportaria incorretamente "não existe". A Opção B é a correta: !errors.Is(err, os.ErrNotExist) retorna true tanto quando o arquivo existe (err == nil) quanto quando há outro erro (permissão negada — o arquivo existe, só não está acessível). A Opção C funciona para arquivos, mas falha para diretórios com permissão de execução mas não leitura.
Exercício 1 — Scanner sem verificação de erro Aplicação prática

O código abaixo conta linhas de um arquivo grande. Em testes com arquivos pequenos funciona perfeitamente, mas em produção ocasionalmente retorna contagens erradas sem nenhum erro reportado. Qual é a causa?

go 
func contarLinhas(path string) (int, error) {
    f, err := os.Open(path)
    if err != nil {
        return 0, err
    }
    defer f.Close()

    scanner := bufio.NewScanner(f)
    count := 0
    for scanner.Scan() {
        count++
    }
    return count, nil  // scanner.Err() nunca é verificado
}
✓ Correto! scanner.Scan() retorna false em dois casos: EOF (normal) e erro de IO (problema). Sem verificar scanner.Err() após o loop, é impossível distinguir os dois. Se um erro de IO ocorrer no meio de um arquivo grande (erro de disco, rede, timeout), a contagem será parcial e retornada como se fosse completa — sem nenhum erro reportado ao chamador. A correção: 
for scanner.Scan() { count++ }
if err := scanner.Err(); err != nil {
    return 0, fmt.Errorf("lendo %s: %w", path, err)
}
Exercício 2 — io.Copy vs ReadAll para arquivos grandes Aplicação prática

Um serviço precisa servir o download de arquivos que podem ter vários gigabytes. O código atual causa crashes por OOM (Out of Memory) em produção. Qual é a causa e a correção?

go 
func servirArquivo(w http.ResponseWriter, r *http.Request, path string) {
    data, err := os.ReadFile(path)  // lê arquivo INTEIRO na memória
    if err != nil {
        http.Error(w, "não encontrado", 404)
        return
    }
    w.Header().Set("Content-Length", fmt.Sprintf("%d", len(data)))
    w.Write(data)  // envia tudo de uma vez
}
✓ Correto! os.ReadFile carrega o arquivo inteiro em um []byte na heap. Um arquivo de 4GB cria um slice de 4GB na RAM — e com múltiplas requisições simultâneas, o processo rapidamente esgota a memória. A solução é io.Copy(w, f): ele usa um buffer interno de 32KB, lendo e enviando em fatias sem jamais ter o arquivo completo na memória. O uso de RAM é O(1) independente do tamanho do arquivo. Na prática, use http.ServeFile ou http.ServeContent — eles também cuidam de Range requests, ETags e Content-Type automaticamente.
