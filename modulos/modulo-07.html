if / else if / else

O if avalia uma expressão booleana e executa um bloco de código se ela for true. Em Go, a condição não precisa de parênteses — mas as chaves são obrigatórias, mesmo para blocos de uma única linha.

go sintaxe básica 
idade := 20

if idade >= 18 {
    fmt.Println("maior de idade")
}

// Com else
if idade >= 18 {
    fmt.Println("maior de idade")
} else {
    fmt.Println("menor de idade")
}

// Com else if
if idade < 13 {
    fmt.Println("criança")
} else if idade < 18 {
    fmt.Println("adolescente")
} else {
    fmt.Println("adulto")
}

Sem parênteses na condição

Em C, Java e muitas outras linguagens, os parênteses em torno da condição do if são obrigatórios. Em Go, são proibidos pelo gofmt — ele os remove automaticamente se você os escrever. A condição é uma expressão booleana simples, sem delimitadores:

go 
// ✓ Correto — sem parênteses
if x > 0 {
    fmt.Println("positivo")
}

// ✗ Estilo errado — gofmt remove os parênteses
if (x > 0) {
    fmt.Println("positivo")
}

// ✗ Erro de compilação — chaves obrigatórias mesmo com uma linha
if x > 0
    fmt.Println("positivo")  // syntax error

Go não converte outros tipos para bool

Já mencionamos no módulo de tipos, mas vale reforçar aqui: a condição do if deve ser uma expressão estritamente booleana. Em C, if (1) ou if (ptr) são idiomas comuns. Em Go, isso não compila.

go 
n := 1
ptr := &n

// ✗ ERRO — int não é bool
if n {
    fmt.Println("não funciona")
}

// ✗ ERRO — ponteiro não é bool
if ptr {
    fmt.Println("não funciona")
}

// ✓ Correto — expressão booleana explícita
if n != 0 {
    fmt.Println("n é diferente de zero")
}

if ptr != nil {
    fmt.Println("ptr não é nil")
}
else fica na mesma linha que }
Pelo mesmo motivo da chave de abertura — inserção automática de ponto e vírgula — o else deve ficar na mesma linha que o } do bloco anterior. Se você colocar o else na linha seguinte, o compilador insere ; após } e o else fica inesperado — erro de sintaxe.

if com inicialização

Go tem uma forma especial de if que permite executar uma instrução de inicialização antes de avaliar a condição. A instrução e a condição são separadas por ponto e vírgula:

go sintaxe 
if instrução; condição {
    // bloco
}

O uso mais comum é capturar o retorno de uma função e verificar o erro na mesma expressão:

go padrão idiomático 
// Sem inicialização — verboso
arquivo, err := os.Open("dados.txt")
if err != nil {
    log.Fatal(err)
}
_ = arquivo

// Com inicialização — idiomático em Go
if arquivo, err := os.Open("dados.txt"); err != nil {
    log.Fatal(err)
} else {
    fmt.Println("arquivo aberto:", arquivo.Name())
}

Escopo da variável inicializada

A variável declarada na inicialização existe apenas dentro do bloco do if — incluindo os blocos else if e else. Ela não vaza para o escopo externo. Isso é precisamente o ponto: limitar a variável ao contexto onde ela faz sentido.

go escopo da inicialização 
if val, err := strconv.Atoi("42"); err != nil {
    fmt.Println("erro:", err)
} else {
    fmt.Println("valor:", val)  // val existe aqui
}

// fmt.Println(val)  // ERRO: val não existe fora do if

Quando usar vs quando evitar

Use o if com inicialização quando a variável declarada só faz sentido dentro do bloco condicional — isso mantém o escopo enxuto e a intenção clara. Evite quando você precisar da variável após o bloco — nesse caso, declare-a antes.

go quando evitar 
// Precisa de arquivo após o if — declare fora
arquivo, err := os.Open("dados.txt")
if err != nil {
    log.Fatal(err)
}
defer arquivo.Close()  // arquivo é necessário aqui fora
processar(arquivo)

switch

O switch em Go é mais poderoso e mais seguro que em C. A diferença fundamental: em Go, cada case não cai no próximo automaticamente (no fallthrough by default). Não é necessário escrever break — ele está implícito.

Expression switch — o mais comum

Compara uma expressão com valores em cada case:

go expression switch 
diaSemana := "segunda"

switch diaSemana {
case "segunda", "terca", "quarta", "quinta", "sexta":
    fmt.Println("dia útil")
case "sabado", "domingo":
    fmt.Println("fim de semana")
default:
    fmt.Println("dia inválido")
}

// switch com expressão numérica
nota := 8

switch {
case nota >= 9:
    fmt.Println("A")
case nota >= 7:
    fmt.Println("B")
case nota >= 5:
    fmt.Println("C")
default:
    fmt.Println("F")
}
switch sem expressão
Quando switch não tem expressão (como o segundo exemplo acima), cada case é avaliado como uma condição booleana independente. Isso é equivalente a uma cadeia de if / else if, mas mais legível quando há muitos casos.

switch com inicialização

Assim como o if, o switch aceita uma instrução de inicialização antes da expressão:

go 
switch os := runtime.GOOS; os {
case "linux":
    fmt.Println("Linux")
case "darwin":
    fmt.Println("macOS")
case "windows":
    fmt.Println("Windows")
default:
    fmt.Printf("outro: %s\n", os)
}

fallthrough — quando você quer cair no próximo

Se você explicitamente quer que a execução continue no próximo case, use fallthrough. Ele força a execução do bloco seguinte incondicionalmente — sem verificar a condição do próximo case:

go fallthrough 
n := 1

switch n {
case 1:
    fmt.Println("um")
    fallthrough  // executa o próximo caso incondicionalmente
case 2:
    fmt.Println("dois")
case 3:
    fmt.Println("três")
}

// Saída:
// um
// dois    ← executado por causa do fallthrough, mesmo n não sendo 2
fallthrough é raro e deve ser explícito
Em C, esquecer o break é um bug comum e silencioso. Em Go, o fallthrough é opt-in — você escreve explicitamente quando quer esse comportamento. Na prática, é raramente necessário. Se você se encontrar usando fallthrough com frequência, considere reestruturar a lógica.

Type switch — switch sobre tipos

O type switch é uma forma especial que verifica o tipo dinâmico de um valor em vez do seu valor. É fundamental ao trabalhar com interfaces — especialmente interface{} (ou any), que pode conter qualquer tipo. Estudaremos interfaces em profundidade no Módulo 17; por ora, veja a sintaxe e o uso:

go type switch 
func descrever(i interface{}) {
    switch v := i.(type) {
    case int:
        fmt.Printf("inteiro: %d\n", v)
    case string:
        fmt.Printf("string: %q (len=%d)\n", v, len(v))
    case bool:
        fmt.Printf("bool: %t\n", v)
    case []int:
        fmt.Printf("slice de int com %d elementos\n", len(v))
    default:
        fmt.Printf("tipo desconhecido: %T\n", v)
    }
}

descrever(42)           // inteiro: 42
descrever("olá")        // string: "olá" (len=3)
descrever(true)         // bool: true
descrever([]int{1,2,3}) // slice de int com 3 elementos

Note a sintaxe especial: i.(type) só é válida dentro de um switch. A variável v recebe o valor com o tipo correto em cada case — dentro do case int, v já é um int, não um interface{}.

if vs switch — quando usar cada um

Situação Preferir
1 ou 2 condições simples if / else
3 ou mais valores discretos da mesma variável switch
Condições com intervalos ou expressões complexas switch sem expressão
Verificar tipo dinâmico de interface type switch

Exercício 1 — Análise de código Aplicação prática

O código abaixo tem um erro de compilação. Qual é o problema?

go 
package main

import "fmt"

func main() {
    x := 5
    if x {
        fmt.Println("x é verdadeiro")
    }
}
✓ Correto! Go não faz conversão implícita de tipos para bool. O compilador rejeita if x com "non-boolean condition in if statement". A correção é if x != 0 — explícito e claro.

Uma função recebe um código HTTP (int) e deve retornar uma descrição em string. Os casos são: 200 → "OK", 301 → "Moved Permanently", 404 → "Not Found", 500 → "Internal Server Error", qualquer outro → "Unknown". Qual estrutura é mais adequada?

✓ Correto! Quando há múltiplos valores discretos da mesma variável, switch é mais legível que uma cadeia de if/else if. O type switch não se aplica aqui — todos os códigos são int. O switch sem expressão seria desnecessariamente verboso para comparações de igualdade simples.
