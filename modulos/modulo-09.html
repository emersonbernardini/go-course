Por que estudar arrays antes de slices
Na prática, você usará slices com muito mais frequência que arrays. Mas entender arrays é obrigatório antes de slices, pois slices são uma abstração construída sobre arrays. Sem entender o que é um array, os comportamentos de slice — especialmente o compartilhamento de memória — parecerão magia e serão fonte de bugs.

Declaração e inicialização

Um array é uma sequência de elementos do mesmo tipo, armazenados em posições contíguas de memória. O tamanho é definido na declaração e faz parte do tipo — não pode mudar depois.

go declaração 
// Sintaxe: var nome [tamanho]tipo
var a [3]int      // [0 0 0] — zero values
var b [5]string   // ["" "" "" "" ""]
var c [4]bool     // [false false false false]

Array literal

A forma mais comum de criar um array com valores é o array literal — todos os valores listados entre chaves:

go 
// Array literal com tamanho explícito
primos := [5]int{2, 3, 5, 7, 11}

// Tamanho inferido com ... — Go conta os elementos
vogais := [...]string{"a", "e", "i", "o", "u"}
// equivalente a [5]string{"a", "e", "i", "o", "u"}

// Inicialização parcial — elementos não especificados recebem zero value
parcial := [5]int{1, 2}  // [1 2 0 0 0]

// Inicialização por índice — útil para arrays esparsos
espaco := [5]int{0: 10, 4: 50}  // [10 0 0 0 50]

Acesso a elementos

Elementos são acessados pelo índice entre colchetes. Índices começam em 0. Acessar um índice fora dos limites causa um panic em tempo de execução — não um erro de compilação (a menos que o índice seja uma constante conhecida em compile-time):

go 
primos := [5]int{2, 3, 5, 7, 11}

fmt.Println(primos[0])   // 2 — primeiro elemento
fmt.Println(primos[4])   // 11 — último elemento
fmt.Println(primos[5])   // PANIC: index out of range [5] with length 5

primos[0] = 100          // modificação
fmt.Println(primos)      // [100 3 5 7 11]

// len() retorna o tamanho do array
fmt.Println(len(primos)) // 5

Tamanho fixo como parte do tipo

Em Go, o tamanho de um array faz parte do seu tipo. Isso significa que [3]int e [4]int são tipos completamente distintos — tão distintos quanto int e string. O compilador os trata como incompatíveis.

go tipos incompatíveis 
var a [3]int
var b [4]int

a = b  // ERRO: cannot use b (type [4]int) as type [3]int

// Uma função que aceita [3]int não aceita [4]int
func soma3(arr [3]int) int {
    return arr[0] + arr[1] + arr[2]
}

soma3(a)  // OK
soma3(b)  // ERRO: cannot use b (type [4]int) as type [3]int

Arrays são valores — não referências

Este é o comportamento mais importante de entender sobre arrays em Go: arrays são tipos de valor. Quando você atribui um array a outra variável ou passa para uma função, uma cópia completa dos dados é feita. Modificar a cópia não afeta o original.

go arrays são copiados 
a := [3]int{1, 2, 3}
b := a          // b é uma cópia completa de a

b[0] = 100      // modifica b
fmt.Println(a)  // [1 2 3] — a não foi afetado
fmt.Println(b)  // [100 2 3]

// O mesmo acontece ao passar para funções
func dobrarPrimeiro(arr [3]int) {
    arr[0] *= 2  // modifica a cópia local
}

dobrarPrimeiro(a)
fmt.Println(a)  // [1 2 3] — a permanece inalterado
Cópias de arrays grandes têm custo
Copiar um [1000000]int significa copiar ~8MB de dados (1M × 8 bytes). Se precisar passar um array grande para uma função sem copiar, use um ponteiro: func f(arr *[1000000]int). Na prática, esse é um dos motivos pelos quais slices são preferidos a arrays na maioria dos casos.

Comparação de arrays

Como arrays são valores, dois arrays podem ser comparados com == se seus elementos forem comparáveis. A comparação é elemento a elemento:

go 
a := [3]int{1, 2, 3}
b := [3]int{1, 2, 3}
c := [3]int{1, 2, 4}

fmt.Println(a == b)  // true  — mesmos elementos
fmt.Println(a == c)  // false — terceiro elemento difere
// a == [4]int{1,2,3,4}  // ERRO: tipos diferentes

Iteração sobre arrays

Há duas formas de iterar sobre um array: com for clássico usando índice, e com for range. O comportamento é análogo ao que vimos com slices no módulo anterior.

go formas de iteração 
notas := [5]float64{7.5, 8.0, 6.5, 9.0, 8.5}

// For clássico — quando precisar do índice para cálculos
for i := 0; i < len(notas); i++ {
    fmt.Printf("Aluno %d: %.1f\n", i+1, notas[i])
}

// For range — idiomático, preferido
for i, nota := range notas {
    fmt.Printf("Aluno %d: %.1f\n", i+1, nota)
}

// Apenas os valores (sem índice)
soma := 0.0
for _, nota := range notas {
    soma += nota
}
media := soma / float64(len(notas))
fmt.Printf("Média: %.2f\n", media)  // 7.90

range sobre array copia os elementos

Como arrays são tipos de valor, o range opera sobre uma cópia do array — mas na prática isso raramente importa para leitura. O que importa: modificar v dentro do range não modifica o array original. Para modificar, use o índice:

go 
nums := [3]int{1, 2, 3}

// ✗ Não modifica o array — v é uma cópia do elemento
for _, v := range nums {
    v *= 2  // modifica a cópia local, nums não muda
}
fmt.Println(nums)  // [1 2 3]

// ✓ Modifica o array — usa o índice
for i := range nums {
    nums[i] *= 2
}
fmt.Println(nums)  // [2 4 6]

Arrays multidimensionais

Go suporta arrays de arrays — arrays multidimensionais. São declarados aninhando os tamanhos:

go 
// Matriz 3x3
var matriz [3][3]int

// Inicialização literal
tabuleiro := [3][3]string{
    {"X", "O", "X"},
    {"O", "X", "O"},
    {"X", "O", "X"},
}

// Acesso: linha, coluna
fmt.Println(tabuleiro[1][2])  // "O" — linha 1, coluna 2

// Iteração com range aninhado
for _, linha := range tabuleiro {
    for _, celula := range linha {
        fmt.Printf("%s ", celula)
    }
    fmt.Println()
}

Limitações e quando usar arrays

Arrays em Go têm limitações significativas que explicam por que slices são a estrutura de sequência padrão na linguagem. Entender essas limitações é fundamental para tomar a decisão certa entre array e slice.

Limitação 1: tamanho fixo e imutável

O tamanho de um array é definido em compile-time e nunca pode mudar. Não é possível adicionar ou remover elementos. Se você precisa de uma coleção que cresce ou diminui, precisa de um slice.

go 
a := [3]int{1, 2, 3}
// Não existe append para arrays:
// a = append(a, 4)  // ERRO: append só funciona com slices

Limitação 2: tamanho deve ser conhecido em compile-time

O tamanho de um array precisa ser uma constante — não pode ser uma variável calculada em tempo de execução:

go 
n := 10
// var a [n]int  // ERRO: non-constant array bound n

const M = 10
var b [M]int  // OK: M é constante

Limitação 3: funções inflexíveis

Uma função que aceita [3]int não aceita [4]int. Isso torna difícil escrever funções genéricas que operem em arrays de qualquer tamanho. Slices resolvem isso elegantemente.

Quando arrays são a escolha certa

Apesar das limitações, há casos onde arrays são superiores a slices:

  • Tamanho fixo e conhecido: uma chave criptográfica SHA-256 sempre tem exatamente 32 bytes — [32]byte expressa isso com precisão e segurança de tipo.
  • Sem alocação no heap: arrays pequenos vivem na stack quando possível, sem pressão no garbage collector. Slices sempre têm um backing array no heap.
  • Comparabilidade: arrays podem ser usados como chaves de map (pois são comparáveis); slices não.
  • Semântica de valor: quando você quer que a atribuição faça uma cópia completa por design.
go casos de uso reais 
// Chave criptográfica — tamanho fixo por especificação
type SHA256Hash [32]byte
type AESKey [16]byte

// Array como chave de map — slice não pode ser chave
cache := map[[2]int]string{}
cache[[2]int{1, 2}] = "ponto(1,2)"

// Posição 2D com semântica de valor
type Ponto [2]float64
p1 := Ponto{3.0, 4.0}
p2 := p1  // cópia intencional — p2 é independente
Regra prática
Na dúvida, use slice. Arrays são para casos específicos onde o tamanho fixo é uma propriedade do domínio (chaves cripto, coordenadas, protocolos de rede com campos de tamanho fixo) ou onde a comparabilidade é necessária. Para tudo mais — listas, coleções, sequências de tamanho variável — slice é a ferramenta certa.
Quiz · Questão 1 de 3 Verificação de entendimento

O que é impresso pelo código abaixo?

go 
a := [3]int{1, 2, 3}
b := a
b[0] = 99
fmt.Println(a[0], b[0])
✓ Correto! Arrays são tipos de valor em Go. b := a cria uma cópia completa e independente. Modificar b[0] não tem nenhum efeito sobre a. Essa é a diferença fundamental entre arrays e slices — que estudaremos no próximo módulo.
Quiz · Questão 2 de 3 Verificação de entendimento

Por que o código abaixo não compila?

go 
func imprimirTres(a [3]int) {
    fmt.Println(a)
}

arr := [4]int{1, 2, 3, 4}
imprimirTres(arr)
✓ Correto! Em Go, [3]int e [4]int são tipos distintos — tão distintos quanto int e string. Isso é precisamente uma das limitações que tornam slices mais práticos: uma função que aceita []int (slice) funciona com qualquer tamanho.
Quiz · Questão 3 de 3 Verificação de entendimento

Por que um array pode ser usado como chave de map, mas um slice não?

✓ Correto! Maps exigem que as chaves sejam comparáveis — que possam ser testadas com ==. Arrays são comparáveis (dois arrays com os mesmos elementos são iguais). Slices não são comparáveis em Go — não existe == entre slices (exceto comparação com nil). Por isso, slices não podem ser chaves de map.
Exercício 1 — Modificação via range Aplicação prática

Um desenvolvedor quer dobrar todos os elementos do array. O código abaixo funciona como esperado?

go 
nums := [4]int{1, 2, 3, 4}
for _, v := range nums {
    v *= 2
}
fmt.Println(nums)
✓ Correto! v no range é uma cópia do elemento — modificá-lo não afeta o array original. Para modificar, use o índice: for i := range nums { nums[i] *= 2 }. Esse é um dos erros mais comuns ao começar com Go.
Exercício 2 — Escolha de estrutura Aplicação prática

Um sistema criptográfico precisa armazenar e comparar hashes SHA-256. Cada hash tem sempre exatamente 32 bytes. O sistema também precisa usar hashes como chaves em um cache (map). Qual tipo é mais adequado?

✓ Correto! [32]byte é a escolha ideal aqui: o tamanho fixo faz parte do domínio (SHA-256 sempre tem 32 bytes), é comparável com == (pode verificar igualdade de hashes diretamente) e pode ser usado como chave de map. A stdlib do Go usa exatamente esse padrão — por exemplo, crypto/sha256 retorna [32]byte.
